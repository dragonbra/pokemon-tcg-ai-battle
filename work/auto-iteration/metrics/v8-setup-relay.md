# V8 Setup and Relay Metric Profile

Profile revision: `2`

## Profile scope

本 profile 用于观察 Alakazam 策略的四类观测内容，并按三层优先级解释：

1. 总体、先手和后手的真实胜率；
2. 己方第二个回合是否实际完成 Alakazam 进攻，以及过牌和替代路线的状态；
3. 可攻击的 Active Alakazam 被击倒后，下一回合能否立即用另一只 Alakazam 接力；
4. 攻击已经发起但没有因此拿奖赏的惩罚项。

每次 full evaluation 固定为 `17 个对手 × 10 局 = 170 局`。这表示对手覆盖和总局数，
不表示先手、后手各固定 85 局。报告必须记录实际先手/后手样本数，并按实际样本计算两种
方向的结果。control 和 candidate 必须使用相同的对手、局数、规则版本、运行配置、异常
归属和 profile revision。

原始 trace 保留对手标识用于审计和干扰归因；第二回合 Alakazam 指标的主结论合并全部
对手，不展示按对手拆开的第二回合成功率矩阵。对手维度仍可用于定位 case 和检查样本覆盖。

## Profile priority

当前 profile 的结果解释严格按以下顺序进行：

1. **第一优先级：胜率和二回合实际发起 Alakazam 进攻的概率。** 先检查总体、实际先手、
   实际后手样本是否改善或发生回退；
2. **第二优先级：Post-KO 立即接力。** 在第一优先级没有不可接受回退后，观察复杂干扰
   下的整体接力成功率和 `recoverable_discard_miss`；
3. **第三优先级：攻击但未拿奖赏率。** 这是越低越好的惩罚项，用于发现 Powerful Hand
   伤害不足、目标选择或资源利用问题，不能反过来覆盖前两级的回退。

第二回合过牌张数和四组件状态是第一优先级下的解释性观测；它们帮助提出假设，不单独
决定 promotion。

## 1. 胜率

### 事件和分母

- 总体胜率：`wins / 全部评测对局`，同时报告胜、负、和、error 和总样本；
- 先手胜率：只使用实际先手对局；
- 后手胜率：只使用实际后手对局。

error、未完成对局和对手错误必须单独报告，不能为了改善比例而静默从分母删除。若
correctness gate 发现 agent error，不能用过程指标或胜率上涨抵消。

### 角色

胜率是最高优先级结果指标，也是长期 `90%` 目标的顶层观测。任何过程指标改善都必须回到
总体、先手和后手胜率检查是否出现未解释的明显回退。

## 2. 第二回合 Alakazam 实际攻击

### 统一回合和成功事件

“第二回合”指己方第二个回合：先手对应 engine turn 3，后手对应 engine turn 4。成功事件
不是“手上有 Alakazam”或“界面存在合法 option”，而是 trace 中 Agent 实际选择
`attackId=1072`，即真正提交 Alakazam 的攻击。

主指标为：

`实际选择 attackId=1072 的对局数 / 全部评测对局数`

主报告展示总体、实际先手、实际后手三行，并合并 17 个对手。该指标优先用于观察策略的
二回合基础能力是否稳定提升；按对手的数值只作为诊断证据，不作为本阶段的主排序。

### 四组件状态观测

四组件不再是“机会率”或“完成率”指标，也不作为 promotion 门槛。它只记录第一回合起始
状态，用来解释一局为什么有或没有资源基础，并帮助区分“资源尚未出现”和“资源出现后
策略没有使用”。四个状态分别是：

1. `Active Abra`：第一回合起始时 Active 是 Abra；
2. `Rare Candy`：第一回合起始手牌有 Rare Candy；
3. `Alakazam 或检索路线`：手牌有 Alakazam、Poke Pad、Hilda 或 Dawn 任一张；
4. `Psychic Energy 或 Hilda`：手牌有 Psychic Energy，或有 Hilda 作为获取 Psychic
   Energy 的路线。

报告逐项展示四个状态的出现次数，并可额外展示“四项同时满足”的状态次数。这个联合状态
仍然只是观测，不计算“具备后攻击完成率”，不把稀有的起手资源组合当成策略质量的主要
结论。替代卡牌的语义必须在后续 evaluator 实现中保持一致。

### 无 Abra 的 Dunsparce 换位路线

这是二回合指标下的高价值情形，不是四组件指标的替代名称。机会样本为：第一回合起始没有
Active Abra、且 Active 是 Dunsparce 的对局。

成功事件必须能够从 trace 或 evaluator 的动作事实确认：

1. 合法完成 Dunsparce → Dudunsparce 进化；
2. 使用 Dudunsparce 的特性完成换位，而不是把 `Trading Places` 当成攻击；
3. Alakazam 合法来到 Active；
4. 己方第二回合实际选择 `attackId=1072`。

当前轻量 trace 只能用“看见 Dudunsparce、第二回合 Active Alakazam 且实际攻击”作为保守
代理，不能声称已经证明特性换位动作本身。未来 evaluator 提供选项级或动作级事实后，
应升级事件识别；口径变化必须提高 profile revision，不能和旧代理直接做 A/B。

## 3. 第二回合平均过牌张数

### 事件定义

从己方第一回合开始，统计到己方第二回合结束的 `LogType.Draw`。主指标只统计由 Ability
或卡牌效果产生的额外抽牌张数；回合开始的正常抽牌必须单独计数并排除在主指标之外。

报告同时展示：

- 全部对局平均值：额外抽牌总张数 / 全部评测对局数；未到达己方第二回合的对局按 0 张
  进入这一口径，因此不能单独解读；
- 实际到达己方第二回合的平均值：额外抽牌总张数 / 实际到达第二回合的对局数；
- 先手实际样本平均值；
- 后手实际样本平均值；
- 正常回合抽牌总数作为审计字段，不并入主指标。

这个指标的方向通常是越高越好，但不能脱离牌库压力和攻击结果解释。过牌增加而二回合
攻击、胜率或牌库闭环变差时，不能直接 promotion；应分析是否是无效过牌、时机错误或
过度消耗资源。相反，在胜率短期持平时，额外过牌稳定增加且二回合实际攻击没有回退，
可以作为接近长期目标的机制证据。

## 4. Post-KO 立即接力

### 机会和成功

机会定义：前一个己方回合的 Active 是可攻击的 Alakazam，随后它离场并进入下一个己方
回合。成功定义：下一个己方回合内，另一只 Alakazam 合法来到 Active 并实际提交攻击；
不要求这次攻击击倒对手。

主报告展示机会数、成功数和成功率，并按实际先手/后手拆分。复杂对手造成的干扰是这一
阶段的重要背景，因此按对手的失败 case 用于归因，但总体成功率才是阶段主指标。

### 失败分类

分类要优先回答“为什么没有接力”，而不是简单把所有未攻击都算作资源耗尽：

| 分类 | 条件 | 迭代方向 |
| --- | --- | --- |
| `field_route_miss` | 场上仍有 Abra 或可继续进化的路线，但没有接力 | 检查场上动作和顺序 |
| `recoverable_discard_miss` | 场上没有 Abra 线，但弃牌区存在攻击线资源，且没有合理回收 | 本 profile 的重点优化信号 |
| `recoverable_route_incomplete` | 看见场上或弃牌区路线，但当前手牌/行动顺序不足以完成 | 区分资源不足和决策漏做 |
| `nonterminal_no_field_route` | 场上没有路线，但牌库或其他资源仍未到终局耗尽 | 不是彻底没有，继续审计资源路径 |
| `terminal_no_resource` | 场上、弃牌区和牌库都没有必要资源 | 唯一可称为资源彻底耗尽的状态 |

当前 trace 的 `recoverable_discard_miss` 是弃牌区出现攻击线卡牌的保守候选，不证明当时
一定存在合法回收选项。只有 evaluator 补充选项级事实后，才能把它升级为“正确回收机会
未使用”的强归因。该分类下降和接力成功率提升，是本阶段对策略最有价值的正向信号。

## 5. 攻击但未拿奖赏

### 事件和分母

一次攻击先要求 trace 中出现 Agent 实际选择的 attack option，并在后续日志中确认对应的
`type=15` 攻击结算。结算后通过下一状态比较己方 Prize 数量：Prize 数量没有减少，记为
一次“攻击但未拿奖赏”；Prize 状态未知或攻击未结算的记录不计入成功/惩罚分子，并单独
记录为审计数量。

主指标为整体比例：

`已结算且 Prize 状态明确的未拿奖赏攻击数 / 已结算且 Prize 状态明确的攻击总数`

主报告合并全部 17 个对手，同时展示：

- 全部攻击的未拿奖赏率；
- `Powerful Hand (attackId=1072)` 子集的未拿奖赏率；
- 已提交、已结算、未完成和 Prize 状态未知的数量。

这个指标方向是越低越好。它不是胜率，也不是 post-KO 机会率；不能因为它下降就跳过前两
个优先级的检查。

### 归因路径

“攻击但未拿奖赏”只是一种结果信号，不直接证明原因。下一步应围绕以下路径建立 case：

1. **手牌资源不足或没有充分过牌**：检查 Dunsparce 链式操作、Fezandipiti Ability、
   其他抽牌/检索动作是否实际可用和是否被使用；
2. **伤害不足或目标选择错误**：检查攻击前手牌数量、攻击伤害、对手 Active HP，以及
   当时是否存在可用 Boss's Orders 目标切换路线；
3. **特殊能量造成的被动攻击**：检查对手 Active 或场上是否可见 Mist Energy/Fighting
   Energy，以及攻击前是否存在获得并使用 Enhanced Hammer 的合法路线。

当前轻量报告器只负责可靠计算结果比例，并保留每次攻击的 attack ID、Prize 变化和可见
伤害日志；它不能仅凭这些字段证明上述三种原因。未来 evaluator 提供手牌、合法选项、
目标可达性和卡牌效果事实后，才能进一步细分原因。原因分类口径变化时提高 profile
revision，并将仅测量器变化标记为 `measurement_only`。

## 6. 三阶段使用方式

### 阶段 A：二回合基础能力

在同一份 `17×10` full matrix 上，主目标是合并全部对手观察：

- 二回合实际 Alakazam 攻击；
- Active Abra、Rare Candy、Alakazam/检索路线、Psychic Energy/Hilda 四个状态；
- 无 Abra 的 Dunsparce 换位路线；
- 第二回合平均能力过牌张数。

先手/后手使用实际样本数展示。连续多个可比 iteration 没有明显改善，且具体情形不再
出现新的可归因漏做时，才认为基础能力暂时进入稳定区间。这个判断是观察窗口，不是
固定的“一轮就停”阈值。

### 阶段 B：复杂干扰下的接力能力

仍使用同一份 `17×10` full matrix，但重点转为整体 post-KO 接力成功率和
`recoverable_discard_miss`。不同对手的分类只用于定位干扰来源，不能替代整体结论。胜率、
先手/后手结果和 G0 correctness 仍是护栏。

### 阶段 C：攻击质量惩罚项

在前两阶段的主要信号稳定后，使用整体攻击但未拿奖赏率作为第三优先级研究线。目标是
降低 Powerful Hand 无奖赏攻击，并通过上面的三条归因路径提出下一轮唯一主要假设。该
阶段仍使用相同 `17×10` full matrix，不能按单个对手的偶然比例直接晋级。

## 7. 解释和晋级

- 过程指标改善但胜率暂时持平：若机制证据明确、没有核心健康回退，可记录为进步并继续
  重复验证；不把一次平局直接写成长期收益；
- 胜率改善但目标过程指标回退：不能只因胜率上升自动接受，应 `observe` 或 `reject`，
  并查明是否牺牲了未来接力或资源闭环；
- 四组件状态增加：只能说明起始资源分布或卡组机会变化，不能直接归因 agent 变好；
- 平均过牌增加：必须结合二回合实际攻击、牌库剩余和胜率判断是否是有效过牌；
- `recoverable_discard_miss` 下降且接力成功率提升：是本 profile 的强正向证据，但仍需
  correctness、可比样本和重复结果支持 promotion；
- 攻击但未拿奖赏率下降：是第三优先级的正向证据；只有在前两级没有不可接受回退、且
  原因路径得到 case 支持时，才能作为 promotion 的补充证据；
- 分母、事件识别、替代卡牌语义或对手矩阵改变：建立新的 profile revision 或
  `measurement_only` 记录，不做直接 A/B。
