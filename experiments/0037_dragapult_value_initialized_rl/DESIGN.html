方差、护栏与诊断

训练、固定验证与最终 holdout 使用不相交 seed namespace。每轮 rollout 前将该轮全部 job、engine/Search/policy seed、seat、source update 与哈希原子汇总到版本级 artifact/schedules/train_schedules.json；不再生成零碎的 train_update_*.json，但保留完整逐局重建能力。环境护栏只哈希 opponent、seat 和 engine/Search/policy seed；game ID 与 source update 只属于 provenance，不再触发 V2 的假阳性。每 5 updates 运行同一 frozen greedy 512 局。value_diag/* 按官方 turn 0–3/4–7/8–11/12+、距终局 0–1/2–3/4+、focal win/loss/draw 拆分 Value mean、residual 与 GAE/terminal explained variance。

另有 0037 项目级无进展护栏（不是官方规则）：同一 actor 在同一官方 turn 内第 20 次返回完全相同的 selection/action 时立即判该 actor 负；CPU rollout 与 CUDA collector 均在第 20 次（>= 20）触发，换 turn 或 actor 后重置。报告把它单列为 ability_repeat_forfeit、repeated_selection_forfeit 或 CUDA progress_guard，不冒充官方终局原因。

Engine CUDA 可行性

RTX 5080 / CUDA 12.8 上，按根目录 quickstart 对 exact FP32 Update-32 checkpoint 做了 semantic prefix 裁剪、共享 state Encoder 与第一个 Option block、只在适配后的最后 Option block 分叉，并用当前 routed max_count 截断 greedy decode。64 lanes 从 1.880 提升到 11.816 games/s，decoder GPU 时间从 29.740 s 降到 1.241 s。152 lanes 为当前推荐档：152/152 完赛、0 error、9.967 s、15.250 games/s、peak reserved 2.43 GiB；256 lanes 为 14.751 games/s、peak reserved 4.37 GiB。首次静态 512-lane 失败定位到固定赛程 344：Mega Venusaur ex 对手循环 Solar Transfer 及其单选后续，写满 512 条单回合记录并触发 turn_record_overflow；其余两个 unfinished 只是 fail-fast 的连带结果，并非 batch 容量问题。加入第 20 次循环判负后，同一固定 512 job 以固定 4×128 完成 512/512、0 error、0 unfinished，护栏判负索引为 69、344、416、417；第二轮逐局结果、终态 hash 和判负索引完全一致。单批 512 也连续两轮 512/512 且自身完全复现，peak reserved 9.79 GiB，但它与 4×128 在赛程 129 有一局不同，符合 TF32 在不同 batch shape 下改变极近 greedy logits 排序的现象。因此 CUDA 合同固定分片大小与顺序为 4×128，禁止跨拓扑比较强度。此处仍只证明吞吐与稳定性：CUDA reset 尚未承接 0037 独立 Search seed，静态 batch 会等待最长 Episode，且尚未收集 PPO Value/log-prob/target；强度结论继续以 official CPU engine 为准。正式 CUDA PPO collector 下一步需要流式 lane 补位、精确 seed bridge 和行为策略存储。
