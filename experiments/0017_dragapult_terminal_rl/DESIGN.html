一、项目合同

0017 只服务多龙巴鲁托 ex + 黑夜魔灵。它不使用 0016 胡地模型，也不会在未经审核时开始训练。

唯一奖励

终局胜负

胜利 +1，失败 −1，平局 0，gamma=1.0。Prize、伤害、进化和技能使用都不改变 reward。

无效 Episode

错误不是平局

engine error、agent error、人工 step limit 都被丢弃并单独计数，不会伪装成 reward 0。

强度证据

只认真实引擎对局

rolling 曲线用于训练诊断；版本强度结论仍来自冻结模型在相同 official-engine 合同下的正式评测。

证据分层

层级确定事实不能越界的结论
官方规则进化时机、每回合资源、攻击结束回合、Prize/无可战斗宝可梦/回合开始抽牌失败等终局条件。官方规则不定义“好策略”，也不定义项目 reward。
当前 runtime每次 engine selection 提供合法 options；完整 rollout 从 battle_start 到终局 result。卡牌精确交互以当前卡牌数据和未修改的 official engine 为准。
项目假设BC 起点、value head、KL anchor 和多龙诊断可能提高训练稳定性和可解释性。这些假设必须通过对局证据验证；诊断永不成为奖励。

三、模型与动作概率

0017 复制并固化 0015 所需实现，禁止运行时 import 其他编号训练项目。跨项目 checkpoint 路径只保留 provenance。

保留的 R15 actor

  • 宽度 320，8 heads，4 层主 entity encoder
  • 1 层 causal event reader，4 个 goal roles
  • 2 层 scenario reader，option ScaleGate 初值 0.35
  • 最多 192 entities、128 legal options、16 action tokens
  • exact 60-card registered deck 和 source persona 同时进入 state/options

新增的 critic

最终 source-conditioned state [B, 320] 经过 LayerNorm + MLP + tanh，输出 value [B]，范围约束为 [−1, 1]。它不读取对手隐藏牌、终局标签或任何 actor 不可见信息。

official observation
  → 22 组 actor-visible causal tensors
  → R15 board / resource / event / goal / scenario readers
  → source-conditioned state [B, 320] + options [B, O, 320]
       ├─ autoregressive legal pointer → sampled action + log π(a|s)
       └─ scalar value head            → V(s)

一个 PPO action 是什么

一个 action 是一次 engine selection 返回的有序 option index 列表。训练时，pointer decoder 在“剩余合法 options + 合法时的 STOP”上逐 token 采样。行为概率是每个条件 token 概率的乘积，因此日志概率为所有 token（包括实际 STOP）的 log-prob 之和。新 policy 和冻结 BC reference 使用同一个已采样 prefix 重放，保证 PPO ratio 与 reference KL 的动作语义一致。

四、完整 Episode Rollout

每局都由真实卡组、真实对手 package 和 official engine 完整推进。只有当前学习中的多龙 policy 的决策进入优化数据。

1 · 调度冻结 opponent 权重、seed、seat 和 policy hash
2 · Engine worker每局独立 CPU 进程，运行未修改官方 runtime
3 · GPU inference集中批量编码、采样合法 action、返回 old log-prob/value
4 · 完整终局终局后附加 +1/−1/0；错误和截断丢弃
5 · 更新后释放有界 RAM buffer 被消费，不持久化 raw trace

内存中的最小 trajectory

每个 candidate decision 只保存紧凑 feature tensors、sampled token sequence、behavior log-prob、behavior value、episode/seat/opponent ID 和诊断计数。原始 observation、对手动作 trace、visualize frames 默认不写盘。队列和 buffer 都有硬上界；GPU inference 变慢时 worker 通过 backpressure 等待。

五、Value Calibration 与 PPO

阶段 A

只训练 value head

actor 完全冻结。完整 episode 的每个 candidate state 目标都是终局 z。每个 timestep 权重设为 1/T，使长局和短局对 value loss 的总贡献相同。

阶段 B

保守 PPO pilot

首版只开放 pointer decoder，representation 和 conditioned blocks 保持冻结。固定 BC actor 提供 reference KL 约束，但不改变环境 reward。

GAE 只在完整有效 episode 上计算，advantage 在当前 update batch 内标准化。出现非有限 loss/gradient 时跳过 update；behavior KL 超过阈值时提前停止当前 batch 的剩余 PPO epochs。扩大解冻范围必须进入新的不可变版本。

胜负 reward 正确，不等于训练必然变强。有限对手池上的策略过拟合、BC 遗忘、探索塌缩、seat 偏置以及 sampled win rate 噪声都可能让训练曲线上升而冻结评测下降。因此 holdout、固定 BC reference、KL/entropy 护栏和同合同正式对局都是算法的一部分。

七、磁盘、Checkpoint 与停止护栏

只存模型

checkpoint 仅含 actor/value weights、config、hash、update counter 和摘要。明确禁止 optimizer/scheduler/scaler/replay buffer。

配额

任一监控盘低于 80 GiB 发警告；/ 或 /mnt/c 低于 50 GiB 前 graceful stop；单版本上限 20 GiB。

不宣称 Resume

从模型权重重新启动必须分配新版本，fresh optimizer、fresh rollout，禁止消费旧 trajectory 或向旧 W&B 曲线追加。

自动停止或暂停条件

信号处理
合法动作率低于 100%立即停止更新，按 action contract bug 处理
500 次尝试内 error/truncation 超过 1%暂停 collector，诊断；绝不转为 reward
非有限 actor/value/loss/gradient跳过 update；重复出现则停止版本
behavior KL > 0.02停止当前 rollout batch 的剩余 PPO epoch
holdout greedy 明显下滑不晋级，停止或以新版本调整
磁盘硬线或版本 20 GiB 上限按 retention 清理可再生 checkpoint；否则 graceful stop

Later explicit Vn
只有证据支持时才扩大 actor 解冻或更改 curriculum。
任何语义或超参数变化都新建版本，绝不覆盖。

Rollout 吞吐校准：同一 20-opponent 训练池、CUDA 集中推理、40 场平衡样本下，4/8/12/16 workers 分别为 0.750/1.117/1.397/1.317 episodes/s，全部 0 error。正式训练选择 12 workers；worker 内单线程。Value rollout 从 2,000 缩短为 512，PPO 保持每 256 场更新。

Preflight 证据：3 个 CPU official-engine episodes；CUDA smoke 为 2 个完整 episodes、135 个候选决策、1 个 value epoch、1 个 PPO epoch，所有 loss/KL/ratio/entropy 有限，model-only checkpoint 反读通过，峰值显存 205,267,456 bytes。以上不构成强度证据。

后续版本决策

  1. 六个新 SOTA/BC opponents 是否保持严格 holdout，还是在后续 curriculum 中逐步开放。
  2. decoder-only 有证据后，是否在新版本开放 final scenario/source-conditioned blocks。
  3. 256 episodes/update 与每 20 updates 的冻结 evaluation cadence 是否匹配实际 engine throughput。

上述选择都不改变终局 reward。它们会在对应版本开始 collection 之前写入不可变 manifest。
