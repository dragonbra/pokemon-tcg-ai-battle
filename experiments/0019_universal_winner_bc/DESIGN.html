项目目标

0019 不针对多龙或胡地。它模仿官方对局中所有可审计胜者，目标是让 Encoder 学到跨卡组通用的牌面、资源、时机与合法动作知识；特定构筑的最终决策与胜率由后续 deck-specific BC/RL 完成。

胜者 BC 是高质量动作先验，不是价值函数。离线 loss 或 exact-action 不能替代 official-engine 胜率。

数据流水线

1. ZIP catalog逐成员读取，不完整解压
2. Winner contract唯一正奖励胜者、60 张卡组
3. Raw shards因果 observation + ordered action
4. Model tensors可直接进入 R15 训练

显式条件

每条轨迹包含 exact deck multiset、deck hash、Unicode NFC team identity、source ID、先后手、Episode/player identity 和 payload hash。source 0 专用于部署时的中性 persona。

模型输入

张量Shape用途
entity_cat/num/mask[B,E,7] / [B,E,5] / [B,E]场上与公开区域实体，E≤192
option_cat/mask[B,O,12] / [B,O]官方合法候选，O≤128
registered_*[B,D]exact 60-card 构筑与 multiplicity
ledger_*[B,D,4/15]因果资源账本
event_*[B,T,8/4]已观察事件记忆
source_id[B] int32训练 expert persona；0 为中性部署
targets[B,A+1]最长 64 步 ordered pointer + STOP

网络与训练

R15 backbone：宽度 320、8 heads、4 层 board Transformer、Goal-QKV、事件记忆、2 层 scenario Transformer、option ScaleGate 初值 0.35。输出是 autoregressive legal-option pointer。

  • AdamW，LR 3e-4，weight decay 0.02，BF16
  • 每 epoch 一次 train pass + 一次完整 validation
  • validation 复用同一次 backbone encoding，同时记录真实 expert source 与 source_id=0 的 neutral loss、teacher/greedy exact 和合法率
  • V1 仍以真实 source validation loss 选点；neutral 指标只诊断通用部署差距，不参与反向传播
  • patience 5，min delta 0.001
  • 单 epoch 初估 70–95 分钟；8–15 epochs 约 9–24 小时
  • checkpoint 仅模型权重，不保存 optimizer/RNG/恢复轨迹
  • W&B：0019 · universal_winner_bc · V<n>_<tag>

有余量时的下一步

  1. 中性 persona 蒸馏，缩小训练 source 与部署 source 0 的差距。
  2. 温和 source dropout，始终保留 exact deck conditioning。
  3. 仅在头部来源支配梯度时启用分层采样上限。
  4. 把通用 Encoder 交给 deck-specific Decoder/末层 BC 或 RL。

这些都作为 V1 baseline 之后的单变量实验，不混入首个正式版本。
