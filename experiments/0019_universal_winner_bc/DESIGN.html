项目目标

0019 不针对多龙或胡地。它模仿官方对局中所有可审计胜者，目标是让 Encoder 学到跨卡组通用的牌面、资源、时机与合法动作知识；特定构筑的最终决策与胜率由后续 deck-specific BC/RL 完成。

胜者 BC 是高质量动作先验，不是价值函数。离线 loss 或 exact-action 不能替代 official-engine 胜率。

数据流水线

1. ZIP catalog逐成员读取，不完整解压
2. Winner contract唯一正奖励胜者、60 张卡组
3. Raw shards因果 observation + ordered action
4. Model tensors可直接进入 R15 训练

显式条件

每条轨迹包含 exact deck multiset、deck hash、Unicode NFC team identity、source ID、先后手、Episode/player identity 和 payload hash。source 0 专用于部署时的中性 persona。

网络与训练

R15 backbone：宽度 320、8 heads、4 层 board Transformer、Goal-QKV、事件记忆、2 层 scenario Transformer、option ScaleGate 初值 0.35；source residual 词表为 509，完整模型 17,756,162 参数。输出是 autoregressive legal-option pointer。

  • AdamW，LR 3e-4，weight decay 0.02，BF16
  • 每 epoch 一次 train pass + 一次完整 validation
  • validation 复用同一次 backbone encoding，同时记录真实 expert source 与 source_id=0 的 neutral loss、teacher/greedy exact 和合法率
  • V1 以真实 source validation loss 选点；neutral 指标只诊断通用部署差距，不参与反向传播
  • 17 个完整 epoch 实测 15.15 小时；稳定期约 46.73 分钟 / epoch
  • checkpoint 仅模型权重，不保存 optimizer/RNG/恢复轨迹
  • W&B：0019 · universal_winner_bc · V1_universal_winner_r15

V1 训练结果

V1_universal_winner_r15 的正式选择指标在 Epoch 13 最优：conditioned validation loss 0.253080647，greedy exact 81.2871%，teacher exact 81.2859%，legal action 100%。Epoch 13 同时赢得三项 conditioned 选点指标。

系统在 Epoch 18 validation 进行到 480/1,382 batches 时重启。运行被如实记录为 interrupted，不冒充正常 early stopping；Epoch 18 没有完整指标或 checkpoint。Epoch 13 的 model-only checkpoint 仍完整可用。

neutral persona 的最低 loss 出现在 Epoch 9（0.365444490），Epoch 13 为 0.368793374。这证明 expert-conditioned 最优点与 source-0 部署诊断最优点并不完全一致；BC 指标仍不代表 official-engine 胜率。

Source persona 设计复核

Persona 最早在 0015 引入：当时研究目标明确是 pi(a|s,D,E)，并在部署固定 THIRD PTCG Club；0016–0019 继承并扩大了该结构。它适合复刻指定老师，不等于现在要求的 source-agnostic pi(a|s,D)。

Epoch 13 对同一 validation split 的 conditioned greedy exact 为 81.2871%，neutral 为 74.8431%，相差 6.4440pp；conditioned/neutral loss 分别为 0.253080647 / 0.368793374。因此 81.2871% 不能解释为最终 neutral 部署能力。Persona 分支有 368,320 个参数；source 98 经过 gate/投影后的 state/option residual norm 为 3.8120 / 1.0897，确认它是实际策略输入。

复核结论：V1 保留为 legacy conditioned checkpoint。未来通用 BC 禁止 persona embedding、source dropout 和 persona distillation；source/team 只用于 provenance、切分、去重、采样和分组评测，Actor 只学习 pi(a|s,D)。

下一步

  1. 用相同 audited winner 数据训练完全不含 source tensor/参数的通用 Actor。
  2. 始终保留 exact deck conditioning，并按 source/deck 分组审计冲突和长尾表现。
  3. 按同一个 source-free validation forward 选 checkpoint。
  4. 用 deck-specific official-engine 评测验证迁移，不用单 deck PPO 替代干净 BC 对照。

所有新语义都必须创建严格递增的新版本，不向已中断的 V1 追加训练轨迹。
