04 · 全集新增的五类信息

R1 · measured：R1 保持同一份 V1 cache、可见性边界和 pointer action contract。V10 epoch 25 全 validation 干预显示：关闭全部新增路径 exact-action 下降 1.87pp；ledger / Goal / card capability 分别贡献 1.66 / 1.26 / 0.79pp，但关闭 R1 新增 state / option conditioning 仅下降 0.03 / 0.12pp。结论是 feature 确实被使用，但静态 0.10 conditioning 没有实质改变模型家族。
R2 · strong Scenario ScaleGate：scenario 明确定义为 public-zone、registered-card causal ledger、event、known/unknown opponent hand 四组 actor-visible facts；card capability 是实体/资源语义，Goal-QKV 是独立规划路径，二者不混入 ScaleGate 输入。state 与每个 option 分别读取 scenario bank，独立 MLP 输出 2 × sigmoid 的逐通道正值 scale（0–2），作用于 FiLM residual。初始 scale 为 1.0，而不是 R1 的 0.10；参数量 17,387,842。V11 因外部后台 PTY 关闭 stdout 在首 batch 后以 EIO 失败并保留；真实正式训练为从零启动的 V12_r2_strong_scenario_scalegate。
1 · Card capability

卡能做什么

card ID 指向 cache 内承诺的 ontology sidecar：kind/stage/HP/type/weakness/resistance/retreat、招式费用/伤害、效果原语与 capability。unknown/missing/N/A 分离。

2 · Public zone inventory

双方各区有多少资源

Active/Bench/hand/discard/deck/Prize 数量及公开场面聚合。对手隐藏区只有 count。

3 · Own resource ledger

己方资源在哪里

每种 registered identity 的初始数、公开区数、deck/Prize exact/bounded/unknown、来源事件与年龄。

4 · Causal event memory

刚刚发生了什么

真实 numeric engine log，按 decision + ordinal 去重并跨 decision 累积；对手 unseen draw 只增加 unknown slot，redacted 离手不保留虚假确定性。

5 · Registered deck

自己的完整构筑

本 episode-player 实际 60 张 identity multiset 与 multiplicity；不推断对手隐藏 deck。

05 · 规则与可见性门禁

语义正确表示禁止
攻击turn-ending commitment；action 前仍保留 Supporter/Energy/Retreat 等状态。使用攻击后的未来状态帮助当前选择。
进化appearThisTurn、进化 child/parent 和本回合时机。只看 card ID 就假定可进化。
Deck/Prize完整可见 deck + 60-card conservation 后才允许 exact；未知转移局部降级。把 eligible subset 当完整 deck；unknown 当 0。

Eventssource event/cursor 唯一消费；时序和 age 保留。重复消费 cumulative log。

06 · 模型

A0

0010 faithful control

7,154,562 params；d320，4 层，8 heads，FFN960，1 option cross-attention，GRU pointer。只换 raw/split 与训练 runtime。

AC

All-feature causal policy

保留 A0 board trunk；局部 semantic adapter、global zone adapter、per-card resource memory、浅层 event encoder、board-conditioned role retrieval、state/option 独立 normalized zero gates。

R2

Strong dynamic conditioning

四组 scenario summary；state/option scenario attention；独立 Goal-QKV；per-sample、per-option、per-channel 0–2 ScaleGate；强度从 1.0 起步。

R3

Typed early fusion

10,710,722 params；scenario token 进入每层 board Transformer。Epoch 7/15 official engine 为 77.5%/78.5%，晚期 loss 恶化，低于 R2 1.0pp。

R4

Additive family router

14,720,642 params；六路 residual 无条件求和。Epoch 7/13 official engine 为 69.5%/75.5%，证明 family interference 明显。

R5

Option-query scenario memory

12,664,002 params；Epoch 9/15 official engine 为 78.0%/72.5%，证明 query-only 边界可行但后期 residual 严重过拟合。

R6

Sparse family mixture

14,826,888 params；Epoch 7/9 official engine 为 72.0%/74.0%，复杂 router 仍形成真实策略捷径。

R7

Regularized option query

11,946,562 params；Epoch 8/14 official engine 为 72.0%/79.0%，低 scale + dropout 延迟了真实策略能力。

R8

Faithful R2 option only

15,128,322 params；保留 R2 option attention、Goal-QKV、FiLM 与 ScaleGate，删除 low-scale state path 后，Epoch 9/13 official engine 仅为 76.0%/75.5%。

R9

Narrow strong option query

11,946,562 params；保留浅层/窄 route，去掉 evidence dropout，option scale 从 1.0 起步；Epoch 9/13 official engine 均为 76.5%。

R10

Bounded state calibration

17,387,842 params；恢复完整 R2，state scale 限制为 0–0.25、初始 0.05；Epoch 8/13 official engine 为 75.0%/77.5%，说明 state path 有价值但不应永久压低。

R11

Strong dropout option query

11,946,562 params；窄 route、evidence dropout 0.20、option scale 初始 1.0；Epoch 10/14 official engine 为 71.5%/75.5%，没有复现 R7。

R12

State-preserving option dropout

17,387,842 params；完整 R2 state calibration，对 option scenario/Goal 做逐通道 dropout；Epoch 12/22 official engine 为 77.0%/75.0%。

R13

Gradual option scale

17,387,842 params；state scale 初始 1.0，option scale 初始 0.35 并保留逐通道 dropout；Epoch 9/13 official engine 为 72.5%/76.5%。

R14

Scenario modality dropout

17,387,842 params；只对 option scenario 路径使用 per-sample 整体 mask，state/Goal-QKV 完整保留。Epoch 8/10 official engine 为 73.5%/74.0%，全部 evidence-dropout 路线停止。

R15 · SOTA

Deterministic gradual option

17,387,842 params；完整确定性 R2 evidence，state scale 初始 1.0，option scale 初始 0.35。Epoch 8/14 official engine 为 74.0%/82.5%；选择 epoch 14，成为项目 SOTA。

R16

Rule-contract option reader

20,699,202 params；CPU/导出门禁通过，但用户在 V26 epoch 1 结束模型探索。运行记录保留，未形成可参与 SOTA 比较的正式 checkpoint。

Goal-QKV 与 ScaleGate 分离：四个 role query 从 registered-card resource memory 检索 setup / prize / recovery / tempo 证据；ScaleGate 只读取 actor-visible scenario summary。Goal 输出不反向充当“场景事实”，避免规划假设与输入事实循环混合。

07 · 主实验顺序

Run目的后续决策
A0测出 0010 原模型在新单-expert split 上的真实基线与吞吐。通过后直接 AC。
AC全部五类信息 + 结构化轻量 reader，追求竞赛性能。好则扩大容量/reader；差或不稳定才做 A1-A5/Goal-off 等诊断。

08 · 训练效率与记录

Train

每 epoch 一次 update pass；同一 teacher logits 聚合 optimization metrics；无 static train eval、无 train greedy。

Validation / early stop

每 epoch 完整 teacher + greedy；共享一次 encoding，BF16 inference；100 epoch 只是上限，greedy exact 连续 5 epoch 未达到至少 +0.001 的改善即停止。

Pipeline

compact shard、pinned prefetch、non-blocking transfer；worker/shard/batch 先 benchmark。

Telemetry

training_metrics.jsonl → TensorBoard → W&B；TQDM 在 W&B Logs 以受控频率显示 batch、loss、decisions/s；scalar history 每 epoch 只写一次，因此默认 Step 与 epoch 严格一致；失败不得影响本地指标/checkpoint。

A0 不做 option permutation。实测选择 8 个 compiler worker、train batch 256、validation batch 512；BF16 train peak allocation 约 1.70 GiB。W&B 身份已验证为 dragon_bra。

09 · A0 启动门槛

Passed全量 raw visibility audit；0010 codec/collate/logit/greedy parity；full cache commitment；7,154,562 参数；BF16 forward/backward/optimizer；共享编码 validation smoke；本机吞吐 benchmark。
