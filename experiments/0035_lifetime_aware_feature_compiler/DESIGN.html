缓存与 dirty graph

Card 使用稳定 (kind, serial) entity key 与 placement overlay；无附件 leaf 使用带类型护栏的 equality fast path，附件树仍做完整 consumed-field projection。Event 复用 immutable payload 并动态更新 age/relation；option 每步更新，但 prototype semantic expansion 按 normalized key 复用。绝对 card index 不跨 layout 复用，parent/event/option relations 按当前 layout 重定位；duplicate serial 会 fail closed。

V2 实测了 decoded-observation boundary 的 whole-layer/zone version：语义正确，但 525 decisions 中完整 CardLayer 仅命中 10 次，zone 命中主要来自空或很小的区域，dirty zone 仍需 entity traversal 和第二次 assembly，因此该重复扫描没有接入 online path。最终接入的是标准库 C 实现的 protocol-5 type-exact binary commitment，用一次保类型的低成本 commitment 替代 Python recursive card projection；它不改变 Engine JSON，也不会把 True、1、1.0 混为一谈。

V3 将复用边界推进到 39 个 canonical tensors。每个 battle/session 可拥有独立的 PersistentTensorBank：容量管理的 CPU storage 跨 decision 保留，未变化 slot 不再调用 torch.tensor 或重新分配，变化的 ragged rows 原位 patch；空 family 会显式清零 canonical padding row，session reset 会释放全部 buffer。返回 view 的生命周期到本 session 下一次 collate 为止，符合同步 online inference；需要历史快照的调用者必须 clone。

这是真正的 tensor persistence，而不是只缓存 Python record。V3 仍需在 Python 侧比较 canonical rows 来发现 dirty range；下一步由 compiler 直接输出 dirty slot/range token，可以消除这次二次扫描，且仍无需修改 Engine。

Model-static prototype GPU cache

V4 不再在每个 forward 重复执行全部 card/attack/skill/effect 的 encode_all()。Eval mode 在当前 device/dtype 上首次构建后常驻复用；默认 FP16 cache 为 5,573,120 bytes，RTX 5080 首次构建约 2.12 ms。cache 是非 checkpoint runtime attribute，device/dtype 变化与 load_state_dict 会失效。

若任何 prototype 参数可训练，train mode 每次执行带 autograd 的实时编码；若 prototype 参数全部冻结，则 train mode 也可复用 detached cache，同时 Transformer/LoRA/Decoder 继续获得梯度。

Worker-local stateless compiler

V5 只改变 evaluation 调度拓扑。启用 worker_local_compiler 并选择 policy_stateless 后，持有 official-engine battle 的 OS worker 为每个 session/side 维护普通 causal encoder，并在本地调用未经增量化的 stateless canonical compiler。worker 只发送 canonical record 与最小 current/select 控制字段；PyTorch、collate、H2D、模型和 decoder 仍统一位于 resident GPU server。

这消除了并行 Engine 与 batched GPU 之间的单一 Python compiler 漏斗。session、actor、deck 和 chronology 继续隔离，compiler crash 会 fail closed，不会静默退回串行拓扑。V5 不选择 incremental、persistent tensor 或 event/session cache；关闭全部可选 cache 时，canonical record、39 tensors、logits 与 action 仍是同一 stateless 语义。

Resource age-split 原型仅独立验证，未接入 V1：median 改善 23.3%，但 p95 回退 36.1%。周期 shadow mode 也是下一阶段要求，V1 不声称已经实现。

基线与准入

35-decision golden fixture SHA-256：0db50f9991849143aba40053f2c5751f2063f76f4f636bb10e0ad0215b0c254e；扩展 fixture 为 10 条完整 actor-local trajectories、525 decisions、双方 seat、7 套 exact deck，SHA-256：87aa39bb7dd8023db0bd05afa954416519bc4abf64552d4a4eff270288d96485。两者均通过完整 record 与 39 tensors exact parity。原始 full baseline：knowledge 0.127 ms、compiler 0.580 ms、collate 0.454 ms、total 1.190 ms；被拒绝的 coarse whole-layer 路径为 1.237 ms，而 full 为 0.593 ms。

最终 paired/interleaved 基准为 7 repetitions × 5,000 chronological decisions（另有 1,000 warmup）：compiler median 0.574 → 0.430 ms（-25.1%），total 1.166 → 1.069 ms（-8.3%），wall throughput 813.9 → 826.7 decisions/s（+1.6%）；compiler p95 0.820 → 0.934 ms（+14.0%）。因此 V1 未通过性能准入。

V2 最终门禁为 7 repetitions × 10,000 chronological decisions（另有 1,000 warmup）：compiler median 0.591 → 0.437 ms（-26.0%），compiler p95 0.950 → 0.910 ms（-4.3%），total 1.219 → 1.069 ms（-12.3%），wall throughput 734.2 → 769.9 decisions/s（+4.9%）。V2 已修复 V1 的 tail regression，但仍未达到 compiler ≤0.25 ms、relative ≥50% 和 end-to-end ≥10% 的准入目标。

V3 full-vs-persistent 最终门禁同样为 7 × 10,000（1,000 warmup）：full compiler/collate/total 为 0.579/0.448/1.178 ms，persistent 为 0.422/0.411/0.993 ms；total median -15.7%，total p95 1.831 → 1.672 ms（-8.7%），throughput 792.0 → 900.4 decisions/s（+13.7%）。固定 incremental compiler 的 tensor-only paired run 显示 collate median 0.457 → 0.420 ms（-8.1%）、collate p95 1.033 → 0.743 ms（-28.0%）、total median 1.076 → 1.015 ms（-5.7%），证明 tensor persistence 有独立收益。

V4 真实 checkpoint、FP16、batch 64 的 7×100 alternating CUDA benchmark：forward median 13.111 → 10.801 ms（-17.6%），p95 33.660 → 29.380 ms（-12.7%），modeled throughput 4,881 → 5,925 decisions/s（+21.4%），action tensor commitment 完全一致。

严格 official-engine 消融使用同一 0035 source/checkpoint 导出的 cached/uncached packages，每 arm 三次 128-game N16E16。768/768 完成、0 error；median GPU model 20.572 → 17.411 ms/batch（-15.4%），wall 67.068 → 63.279 s（-5.6%），selections/s 335.35 → 355.47（+6.0%）。

V5 相邻 official-engine 对照使用同一 Policy-0806 checkpoint/deck、N16E16、batch 64、2 ms、FP16。中央 stateless 为 128/128、0 error、342.22 selections/s、65.72 s；worker-local stateless 为 128/128、0 error、528.77 selections/s、42.52 s，即吞吐 +54.5%、wall -35.3%。server prepare_records 从 65.51 降至 0.20 ms/batch。worker-local incremental 为 525.77 selections/s，比 stateless 低 0.57%，因此正式选择 stateless。

准入要求：record 与 39 tensors 精确 parity；shadow/logit/action 0 mismatch；compiler ≤0.25 ms 且至少快 50%；128/128 official-engine、0 error；N16E8 至少 +10%；N16E1 不回退超过 3%。通过前默认使用 stateless full path。
