模型数据流

官方引擎 observation
  → 因果 R15 特征编译器（与 0016 相同的 Actor 可见 schema）
  → 冻结的实体 / 资源 / 事件 / 目标 / 场景表征 [B, 320]
      ├─→ 自回归合法动作指针 Decoder（由 PPO 训练）
      └─→ LayerNorm → MLP → tanh Value Head [B]（可训练）

Actor 看不到终局结果或任何对手私有信息。它只能看到合法选项、公开或因果已知状态、 自己注册的完整卡组，以及固定的来源 ID 0。只有满足 minCount 后才能选择 STOP； 官方引擎提供的 mask 始终是不可突破的动作合同。

流式动态批处理

第一个引擎请求到达后开启 2 ms 聚合窗口。窗口内实际到达多少请求，就立即合并为一次 张量前向；服务不会为了凑满固定 batch 而等待。使用 16 个 worker 时，每次候选模型 推理的 batch 可以自然地处于 1 到 16 之间。

不同权重的模型无法共享同一次张量前向。12 模型混合池把 7,507 个请求 拆成了 6,443 次前向，其中 5,386 次的 batch size 只有 1。在这张单独的 RTX 5080 上， 实测最优默认方案是 CPU 并行运行对手、GPU 对候选模型做动态批处理。对手模型常驻 GPU 的能力仍然保留，可通过显式实验开关启用。

证据边界与监控

官方规则定义合法性与终局条件；未经修改的官方引擎产生每一个 Episode 和奖励。PPO 选型属于项目实验假设。W&B run 名固定为 0018_alakazam_terminal_rl-<Vn_tag>。指标先写入本地事实源，再镜像到 TensorBoard 和私有 W&B。

主要实时面板包括：rolling 100/500/2000 胜率及 Wilson 区间；先后手与逐对手胜率； 每秒 Episode 和每秒决策；候选/对手 batch 的平均值、最大值与推理耗时；Policy/Value loss、熵、behavior/reference KL、clip fraction、explained variance；Decoder 相对 BC 与本次更新前的参数位移；固定 1,024 状态上的 greedy 动作翻转率；GPU 显存、利用率 与磁盘警戒线。

当前阶段：V1_value_calibration 已使用官方引擎完成 512 个有效 Episode、36,282 个候选决策，并在冻结 Actor 的前提下训练 Value Head 4 个 epoch；最终训练内 RMSE 为 0.8374，explained variance 为 0.2538。这些数字只用于 Critic 初始化诊断，不是策略强度证据。V2_ppo_decoder_terminal 在保留 update 10 后按计划停止；300-job greedy 诊断中，BC/V1 为 228/299（76.25%），update 1 为 224/300（74.67%），update 10 为 228/298（76.51%，另有 1 平局），没有证明真实 greedy 强度提升或损坏。V2 update 10 的 reference KL surrogate 仅 0.000620，Decoder 相对 BC 位移 0.2599%。

下一阶段：V3_ppo_lambda1_lr1e5_smoke 先验证单次更新合同； 随后 V4_ppo_decoder_lambda1_lr1e5 从干净的 V1 model-only checkpoint 开始，使用 512 局/update、lambda 1.0、2 epochs、Actor LR 1e-5、 零熵奖励和更严格的 behavior KL 护栏。rolling 胜率只作训练诊断；密集 checkpoint 将用于后续官方引擎 frozen-greedy 对比。
