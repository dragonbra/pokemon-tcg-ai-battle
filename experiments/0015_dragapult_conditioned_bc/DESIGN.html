03 · 模型和信息边界

π(a | s, D, E) s = action-time actor-visible board/history + legal full-action options D = exact registered own 60-card multiset E = frozen expert/source persona; target export fixes THIRD PTCG Club allowed: own deck identity/counts, ontology, known zones, bounded/unknown resource ledger, source persona audit only: build family, deck hash, outcome forbidden live inputs: future frame, terminal result, opponent hidden deck or opponent identity

采用选定的 0014 R15 registered-card memory；保留卡牌 identity、初始 multiplicity 和当前资源位置。不同 team 的动作标签通过冻结 source vocabulary 显式条件化，部署时固定目标 persona，不使用对手身份或预设 matchup。

四类 rule token

turn_budget[10]、prize_race[16]、library_pressure[12]、board_relay[19]；全部只来自 actor-visible 当前状态。

Full-width reader

width 320 / 8 heads；总参数 20,728,002。V2 frozen 模式只训练 3,311,360 参数，271 个 inherited tensor 严格载入并冻结。

Prepared low-rank reader

width 80 / 4 heads；总参数 18,054,162、可训练 637,520（减少 80.7%）。CUDA smoke、逐位冻结校验与 portable export 已通过；gate 失败后未分配正式版本。

Rule-reader gate：V9 的全模型 warm-start 即使 LR 1e-4 也迅速破坏 V2；V10–V13 因此冻结基础模型。预声明 gate 要求 V11 或 V12 超过 V2 的 39/200，但两者仅为 38/200 与 29/200，因此停止该路线。V14 独立用于 label smoothing。

05 · 失败对局如何进入 BC

可以使用

数据稀缺时保留经审计的完整失败局；失败是 episode metadata，不代表每一步都错。

暂不做 value

不把终局胜负复制为逐动作 reward/value target，也不假装定位了关键失误。

可控的静态权重

只有出现噪声压制时，比较 bounded episode/source quality 权重；始终另报 unweighted validation 和各 strata 有效权重。

win_weight = 1.0; loss_weight ∈ {0.75, 0.50}; draw_weight = 1.0 L = Σᵢ wᵢ Σₜ maskᵢ,ₜ CE(zᵢ,ₜ, yᵢ,ₜ) / Σᵢ wᵢ Σₜ maskᵢ,ₜ

V4/V5 保留 T1 的全部 54,764 条 train decision，只在训练 CE 中消费 episode outcome；validation、checkpoint 选择、离线指标、candidate 推理和 official-engine 评测全部保持 unweighted。每 epoch 包含 33,601 条胜局 decision 与 21,163 条败局 decision；V4/V5 的平均 decision weight 分别为 0.90339 / 0.80678。

V14 legal-class label smoothing：回到 plain R15，只在训练 token CE 使用 ε=0.05。Pointer decoder 用 dtype minimum 屏蔽非法 class，因此平滑质量只分配给当前 token 的合法 logits；padding 排除，label 必须合法。Validation 仍为 unsmoothed CE + greedy full-action，模型输入、结构和 candidate runtime 与 V2 相同。两次 nonfinite smoke 保留为诊断，修正后的 5-batch CUDA BF16 smoke 已通过。

06 · 唯一成功目标：自爆多龙

评测收口：没有可在本地运行的老师 policy，因此不存在“学生对老师胜率”。纯多龙和宝石海星 + 黑夜魔灵只提供辅助训练数据与诊断，不进入 checkpoint 排名、headline score 或最终 go/no-go。T0–T3 的成功只由我们自己的版本在同一套“多龙 + 黑夜魔灵”目标构筑上的相对变化决定。

离线一致率：诊断轴

只看目标构筑 holdout，判断对老师 logged states 的复现、是否明显学歪，并用同一预声明规则为各 arm 选择 checkpoint。

Official-engine：强度轴

所有 frozen candidate 使用同一目标 deck.csv。真实 W/L/error 是主要终点，因为它评估模型自己行为所诱导出的局面。

动作一致率下降、真实胜率上升并不矛盾：多个动作可能近似等价，辅助数据也可能改善 teacher holdout 很少覆盖的恢复局面。它是有价值的候选结论，但必须由冻结 package 的新 seed 确认，而不是一次点估计。

08 · 二维结果怎么解读

目标构筑一致率目标构筑真实强度结论
上升上升最干净的正迁移。
下降上升可能学到了超越字面模仿的稳健策略；冻结模型新 seed 复现后可视为成功。
上升持平/下降更像老师，但没有更强的实战证据。
下降下降负迁移或确实学歪。

T3 ≈ T3-no-deck 时，只能说辅助数据可能有效，不能说 exact-deck conditioning 已被证明。

09 · 不泄漏的真实对战合同

每 epoch 做目标构筑完整固定 validation，不做大型 engine tournament，也不根据 engine 胜率挑 epoch。所有 arm 使用同一目标-only 离线规则各冻结一个 checkpoint，再导出同一套目标多龙 + 黑夜魔灵 deck.csv。另外按预声明的首个、25%、50%、75%、100% epochs 运行小型 milestone 对局，画出我们自己的训练中胜率曲线，但不拿这条曲线反选 checkpoint。

Target validation统一规则选 checkpoint；不看 engine test
→
Development batch相同 catalog、paired seats/seeds；报告差值与不确定性
→
Fresh confirmation胜者与 T0 用未使用 seeds 复测；package 不再调整

正式报告包括 W/L/error、completion、相对 T0 的 paired win-rate difference、置信区间、先后手和 per-opponent 结果。单次点估计提升只算 exploratory；辅助构筑不参加正式强度评估。
