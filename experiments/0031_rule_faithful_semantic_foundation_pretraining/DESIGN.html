0031 Rule-Faithful Semantic Foundation Pretraining

Status: V2 semantic implementation is training-ready. No formal dataset or run exists. torch.compile is not admitted for formal training.

Evidence Boundary

General rules follow the repository rule research. Concrete card/event semantics come from the unmodified official engine and official_full_engine_prototypes_v2.json. Model and training choices are project hypotheses.

Team Rocket's Energy (card 15) remains the canonical regression: Psychic | Darkness = 80, count 2, Team Rocket restriction, and skill 8. The actor receives physical identity/serial/attachment, static engine facts, and one Pokemon-parented token per official resolved Energy unit. The API does not partition flattened units by physical card, so no mapping is fabricated and the card is never replaced by Colorless or zero Energy.

Learning Boundary

Attack Energy symbols, base damage, effect constants/coefficients/comparators, targets, areas, and conditions are facts. The actor does not receive Energy deficit/surplus, removal advice, attach counterfactuals, newly-enabled flags, post-damage HP, KO labels, source/team/persona, future information, or target leakage. Matching and arithmetic remain model work.

Model And Cost

Default: 320 dimensions, 8 heads, four state layers, three option cross-attention layers, ordered option pointer plus STOP, 56,868,802 parameters. 0028 had 21,837,082; 0031 is 2.60x, mainly from the lossless prototype ontology and typed fields.

Across 512 chronological real decisions, card-family tokens average 55.85 versus 45.11 (+23.8%); 5.87 are resolved Energy units. Median warm feature compile is 0.573 ms/decision versus 0.301 ms for 0025 (1.90x), still below 1 ms. A production-size 0031 epoch has not run, so no exact training slowdown is claimed.

Variable Lengths And Buckets

Cards, events, options, skills, and effects are genuinely variable in count. Semantic records remain ragged; collation pads dense batch tensors and supplies masks. Fixed shape does not mean lost information.

card:   16, 32, 64, 96, 128
event:  8, 16, 32, 64
option: 4, 8, 16, 32, 64
effect: 8, 16, 32, 64, 96, 128
skill:  8, 16, 32, 64
action including STOP: 2, 4, 8, 16, 32, 64

Effect max 64 is invalid: real decisions reach 91. The 96/128 buckets are required; values above 128 fail closed.

At batch 32, fixed buckets add padding but a d64 RTX 5080 eager diagnostic was effectively tied: 243.8 decisions/s dynamic versus 245.1 fixed. This is noise, not a fixed-padding speedup.

Compile Status

Teacher forcing now enters module forward, data-dependent decoder indexing was removed, and a real backend="eager", fullgraph=True regression passes. Model-only saving unwraps compiled modules, so ordinary eager models load clean keys.

Inductor is not ready. Even d32/batch-1 full-prototype compilation created a very large graph and 16 multi-GB compile workers without finishing in the diagnostic window. The sample also had 124 joint bucket signatures across 2,048 decisions. Formal run_bc therefore exposes no compile switch.

Training And Resume

BC performs one train pass and full teacher-forced plus greedy validation per epoch, with private W&B for formal runs. Four model-only slots remain inference/export artifacts. One atomic checkpoint/resume/latest_resume.pt additionally stores model, AdamW, optional scheduler/GradScaler, completed-epoch trainer state, and Python/NumPy/Torch RNG.

Resume requires identical dataset, training config, model contract, and implementation hashes plus agreement with the canonical metrics epoch. The exact boundary is a completed epoch; an interrupted partial epoch is rerun. Estimated peak checkpoint retention is roughly 1.5-1.8 GiB. Resume state never enters a candidate.
