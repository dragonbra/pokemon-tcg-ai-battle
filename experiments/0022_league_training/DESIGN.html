当前合同

Foundation

严格绑定 0019 Epoch 13，17,756,162 参数，SHA-256 da9b13d6…e5bb；source_id 永远为 0，Encoder 长期冻结。

48 Frozen

每套 exact deck 都有 Foundation decoder 质量锚点。训练期间永不更新，用于固定 greedy 回归评测。

48 Live

每套拥有独立 Decoder/Value、trajectory、optimizer 和 model-only checkpoint。dragapult_ex_001 从 update 39 分支，其余 47 套从各自 update 0 开始并在完整 update 中独立更新。

Official engine

每局在隔离 worker 中执行未修改 official runtime。CPU 负责状态转移，双方策略动作由父进程集中 GPU 推理。

运行拓扑

isolated official-engine workers
    │ 128 Torch-light workers · focal + opponent requests (5 ms coalesce)
    ▼
one resident GPU service
    shared frozen Encoder ── one mixed batched forward
       ├── focal Decoder/Value: stochastic behavior action
       └── Foundation Decoder: greedy Frozen/Live-view opponent action
    │ legal ordered action response
    ▼
terminal trajectories → per-deck routed GAE/PPO → decoder/value checkpoints

Live 与 Frozen 是同一 exact deck 的两种策略实例：Frozen 永不更新，Live 按自身 trajectory 更新。两种 view 用于记录质量锚点、调度、provenance 和策略漂移；共享 encoder 只保留一份，reference 也只复制 deck-local decoder/value，不在 GPU 上重复 48 份完整 encoder。

组件训练状态参数/职责

正式更新

48 Frozen views + 48 Live views = 96 matchup identities
512 official-engine games / PPO update
256 focal-first + 256 focal-second
terminal reward: win +1 / loss -1 / draw 0, gamma = 1
every 5 updates: 48 Frozen decks × both seats = 96 greedy games

rollout/source_policy_update=k 表示对局由 update k 的 behavior policy 采集；该批 PPO 生成 checkpoint/update=k+1。正式 update 若缺失任一 Live deck 的真实 decision 则 fail closed。sampled rollout 胜率只作训练诊断，checkpoint 强度以独立 eval/* Frozen/Live greedy gates 和两个 League identity probes 为准。

运行与存储

边界行为
启动磁盘少于 100 GiB free 则拒绝分配 version
运行磁盘少于 80 GiB free 时在完整 update 边界干净停止
Version cap超过 10 GiB 立即失败；不保存 rollout buffer 或 optimizer
Checkpoint每个 deck 保留最新 2 个和每个 gate update 的 snapshot；每个文件原子写入并带 SHA sidecar，版本 cap 前自动清理
训练时限约 20 GPU 小时；到时间后完成当前 update 再结束
人工停止SIGINT/SIGTERM 只设置 stop request；完成当前 update、checkpoint 与指标后在边界退出

证据边界

Frozen 胜率改善只能证明相对当前 48-deck anchor 的局部改进，不能证明全局最优。Live-view rollout、loss、KL 和 reward 不能冒充 checkpoint 强度。真正启用其他 Live deck 的 actor gradient、League 共进化、开放 Encoder 或加入新机制，均必须创建新的不可变版本并重新执行 smoke、Frozen gate 与设计同步。

sampled rollout 胜率始终是 source policy 的训练诊断；Frozen/Live greedy gates 与 League 内两个固定 identity probes 才用于 checkpoint 强度判断。
