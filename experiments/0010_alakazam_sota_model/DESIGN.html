02 / Input schema

每一个输入字段

N <= 192 为实体数，M <= 128 为合法 option 数，T <= 17 包含最多 16 个选择与一个 STOP。batch 内按实际最大长度 padding。

不是把所有字段 concatenate 成一个大向量

同一个 global、entity 或 option token 内，各路 embedding、数值 MLP 或 entity gather 都先变成同样的 320 维，再做逐元素求和（elementwise sum）。唯一的 concatenate 是序列轴：[CLS(global), entity_1, ..., entity_N] 形成 [B, N+1, 320]。option 不拼进这条序列，而是在状态编码完成后，以 cross-attention 读取整条状态序列。

Mask、label 与 STOP

padding 不参与 attention 或 loss

entity_mask [B,N] · bool

标记真实 entity token；Transformer 的 CLS 始终有效，padding entity 被 src_key_padding_mask 屏蔽。它控制 attention，不作为可学习特征输入。

option_mask [B,M] · bool

标记真实合法 option；pointer 还会屏蔽本序列中已经选过的 option。它只控制可选 logits，不进入 token 表示。

targets [B,T] · int64

专家选择的 option index 序列，末尾追加当前 batch 的 option_count 作为 STOP class；padding 为 -100。只进入 teacher forcing 与 loss。

min_count [B] · int64

来自 select.minCount。解码步数未达到它以前，STOP logit 被硬 mask；不进入 state encoder。

max_count [B] · int64

来自 select.maxCount。teacher-forcing loss 不需要它；live greedy pointer 达到该步数时强制结束；不进入 state encoder。

隐藏信息边界

没有对手手牌内容、Prize card IDs、完整初始牌组、卡牌 category、卡文、expert ID、reward 或 value target。

实体编码，再做自回归选择

模型参数为 7,154,562，FP32 权重约 27.29 MiB。state encoder 和 option encoder 共享 card embedding；option 通过 entity reference 读取编码后的来源与目标表示。

State encoder

全局 4 路 embedding + 12 维数值 MLP 注入 CLS；entity 的 7 路 embedding + 5 维数值 MLP 形成 token。4 层、8 heads、FFN 960 的 pre-norm Transformer 编码联合序列。

Option encoder

10 路 option embedding 与 2 路 source / target entity gather 求和；随后以 option 为 query 对完整 state sequence 做 8-head cross-attention，再通过 2× hidden FFN。

Pointer decoder

CLS 初始化 320 维 GRU hidden。每一步对尚未选择的 options 计算 scaled dot-product pointer logit，同时计算 STOP logit；teacher forcing 用专家上一选择更新 GRU。

state, entities = Transformer([CLS(global); entity_tokens]) options = FFN(option_tokens + CrossAttention(option_tokens, [state; entities])) h_0 = tanh(W_init · state) logit(option_i, t) = <W_q h_t, W_k option_i> / sqrt(320) + bias(option_i) logit(STOP, t) = MLP_stop(h_t), masked while t < min_count h_(t+1) = GRU(selected_option_t, h_t) L_BC = CrossEntropy(pointer_logits, target_sequence, ignore_index=-100) # no category feature · no reward weight · no value head · no PPO objective
为什么 validation loss 与 exact-action accuracy 会分叉

loss 是 teacher forcing 下按全部有效 option / STOP token 加总、再除以 token 数的交叉熵；它关心正确答案的完整概率，长动作也会贡献更多 token。exact_action_accuracy 则按 decision 计 0/1：该行所有 token 的 argmax 全对才记 1，但不区分正确答案概率是 51% 还是 99%。因此少量高置信错误可以推高 loss，同时更多边界样本刚好翻到正确 argmax 又会让 exact 上升。二者都不是自由解码或官方 engine 胜率，故分别保留 checkpoint，再用真实对局选择。
