0015 · Outcome-Aware Value Foundations

前瞻性权威设计：在不把败局动作粗暴定罪的前提下，让完整胜败轨迹先服务于 actor-visible value calibration，并把 BC、关键动作归因与真正 RL 分层推进。

prospective · no trainingone deck + one source firstBC + value, not RLofficial-engine required later
当前工作命题：败局不是“每一步都错”的标签。0015 先用它学习从当前可见局面出发的胜率；它可以标出值得审计的崩盘窗口，却不能单靠一条历史轨迹证明哪一个合法动作造成失败。

01 · 问题边界

要做

在同一 deck、同一 expert/source 的完整胜败轨迹上训练并校准 state value，测试它是否帮助第一阶段 BC 表征。

不做

不把所有败局动作当负标签；不启动 PPO/在线 RL；不将 value dip 写成因果结论；不自动晋级 policy。

数据边界

episode 分组切分；完整 provenance；actor-visible action-time state；终局 outcome 只能作 target，不能作输入。

03 · 规则为何是 value 输入的一部分

局面语义对 value 的含义必须保持的边界
Attack commitment攻击结束回合，可能放弃尚未使用的准备资源。只看选择攻击前的状态。
Turn budgetSupporter、手动 Energy、Retreat 的一次性选择会改变后续路线。记录 action-time flags，不读未来结果。
Evolution clock本回合才入场的 Basic 与可进化目标有不同价值。用 audited history / appearThisTurn，不从未来进化反推。
Prize / board / resources胜利、接力和未来起手抽牌风险都依赖它们。未知保持未知；对手 hidden identity 不可见。

04 · value 能说什么、不能说什么

能：标记候选窗口

ΔV = V(s_{t+1}) − V(s_t) 的显著跌落可触发 replay、资源账本和规则时机审计。

不能：证明动作有罪

跌落可能来自随机性、对手回应或未观察的替代路线。单条历史轨迹通常只有一个实际动作。

后来：动作价值

要比较同局面合法替代项，需要 Q(s,a)、优势以及可复现 official-engine counterfactual rollout。

06 · 预注册的测量原则

Value

BCE、Brier、reliability curve、calibration slope/intercept；按 outcome、turn、seat、先后手、长度、Prizes、attack-ready、deck/source 分组并附样本数。

Policy

保持 online diagnostics 与 fixed validation teacher/greedy full-action 分开。JSONL → TensorBoard → W&B。

Strength

只有自包含 candidate 的 official-engine 实战，在同 opponent pool、seat/seed、metric profile 下才是强度证据。

停止条件：发现 outcome/future leakage、source/deck 混合、时序无效、value 低于平凡基线、BC 明显退化或 engine/replay 矛盾时，保留失败版本和证据，不覆盖旧版本。

07 · 明日讨论 Q&A

问题当前答案提交前需要什么证据
败局动作是否训练 policy？默认否；先训练 value，all-outcome BC 是单独 control。P0/P1/P2 对照与 official-engine 结果。
只用胜负够不够？够作第一版、无歧义的 value target；但稀疏，不能归因。outcome audit 和 calibration。
现在要 dense reward 吗？不要；Prize/KO/回合数会改变目标并可能 reward-hack。独立 reward proposal 和消融。
如何找关键错误？ΔV 只做候选；需 Q(s,a) 或受控 engine alternatives。legal-action counterfactual rollout 设计。
能合并多个 deck 吗？0015 第一阶段不能；需明确 deck/source conditioning。独立跨 deck 设计。
何时才算 RL？用当前 policy 的 return 显式优化 policy 时，而不是训练一个 value head 时。新 rollout/reward/Q/PPO 设计。

08 · 明日从何处开始

先选择一个 deck 和一个 normalized expert/team source，审计全部官方完整胜败 episode，冻结 episode-grouped manifest 与 actor-perspective outcome target；之后才建立 P0，并预先写好 λ_v、checkpoint、calibration 与成功门槛。没有此审计，不启动训练、RL、对手晋级或外部提交。
