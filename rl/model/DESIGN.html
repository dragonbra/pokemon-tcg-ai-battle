通用候选策略模型

当前实现把公开牌局状态、完整己方牌组、场上实体、短期历史、专家来源和 simulator 给出的合法动作放进同一个 BC 合同。0003 只使用冻结的 Yushin Ito 数据验证通用表达，并已通过 180 局官方引擎闭环验收；下一批 Top 20 来源已经完成单局审计与隔离 staging，但尚未构建完整训练 corpus。

当前阶段：纯 Behavior Cloning 0003 / V2 · evaluated + submitted 64 state · 40 cards · 64 candidates Top 20 staging · 8 archetypes 下一阶段尚未实现：RL rollout
关于“能否无缝衔接 RL”

模型和 action mask 接口可以直接复用，BC checkpoint 也可以作为 rollout policy 的初始化。

但当前 value head 没有进入 BC loss，rollout schema、reward、old log-prob、return/GAE 和 PPO update 都尚未实现。因此这是结构连续，不是 RL 已经自动完成。

02 / Input contract

模型究竟看到了什么

以下 shape 来自当前 `ptcg_features_universal` 编码器，并已在 0003 的 86,875 条记录上通过一致性审计。

基础状态：64 numeric + 40 card IDs
46 · board / turn / logs / timing 18 · universal context 40 · visible card tokens

前 46 维包含双方 Prize/牌库/手牌/弃牌数量、Bench、Active HP 与能量数、回合与先后手、Supporter/手填能量/Retreat 标志、selection min/max/context、日志摘要、effect context 和 `appearThisTurn` 等时机。新增 18 维补充牌组规模与已知资源、双方场面规模与状态计数、历史长度、effect step、候选数及对手公开资源。

40 个卡牌 token 固定为：双方 Active + Bench 各 6、己方手牌 16、己方弃牌 8、对方弃牌 4。超过槽位会截断；隐藏手牌不会被猜测。

完整己方牌组：60 × (card ID + 18 numeric)
initial copiesin handin discardon fieldestimated remainingremaining ratio

每张初始牌都保留为一个 token，因此模型知道本局使用的确切 60 张己方牌组。每个 token 的前 6 维是资源账本，后 12 维是卡牌结构元数据。`estimated remaining` 只根据可见己方区域计算，不表示真实牌库顺序或 Prize 内容。

场上实体：12 × (card ID + 28 numeric)
双方 Active + 5 Benchowner / zone / slotHP / max HP / damageEnergy / Tool count5 status flagstiming / serial / evolution depth

12 个固定槽位分别对应双方的 Active 与 Bench。前 16 维描述实例状态，后 12 维描述卡牌结构。当前只编码附着 Energy 和 Tool 的数量，不编码它们各自的 card ID；进化链也只有深度，没有完整 stack IDs。

短期历史与 expert 条件：32 × 8 + 1 ID
action typecard / attack IDtarget countselection type / contextrelative positioneffect step

历史保留最近 32 个 decision 的压缩事件，不是跨整局的 recurrent memory。`expert_ids` 给模型一个来源 embedding；0003 为了保持策略一致性，所有记录固定为 Yushin Ito 的 expert ID 1。多 expert 映射与评测尚未验证。

候选动作：64 × (3 IDs + 22 numeric)
action type IDvisible card IDtarget card ID10 option fields12 card metadata

10 个 option 字段是候选位置、area、in-play area/index、attack ID、number 和 selection context。可见候选卡会从手牌、场上、弃牌或搜索区域解析；再附加它的 12 维结构元数据。padding 与非法位置由 `action_mask` 屏蔽。

卡牌结构元数据：12 维，不等于理解卡文
Pokémon / Trainer / EnergyBasic / Stage 1 / Stage 2HPRetreathas weakness / resistancemove counteffect text length

元数据由官方 `EN_Card_Data.csv` 解析，能帮助模型在未见牌组中理解基础类别与身材，但没有编码攻击费用、伤害、弱点类型、Resistance 类型或 effect 的实际语义。`effect text length` 只是复杂度代理，不是文本 embedding。

合法性边界：完全由 simulator options 决定

模型只对 simulator 当前给出的 options 排序；训练和推理都使用同一 `action_mask`，选择数量还受 `minCount..maxCount` 限制。模型不会自行构造规则外动作。这个合同保证输出合法，但不能保证策略正确。

Observation 覆盖性

按模型现在能回答的问题分层：

  • 已覆盖
    己方确切牌组、公开资源、双方场面位置与伤害/状态、回合时机、近期决策、合法候选。
  • 部分覆盖
    卡牌语义、资源账本、附着物、进化链、长程历史。都有摘要，但不是完整表达。
  • 没有覆盖
    对手隐藏手牌、牌库顺序、未知 Prize、对手 deck list、隐藏信息 belief、动作反事实收益。
  • 重要结论
    当前输入比旧合同全面很多，并已在 Yushin Ito 牌组上完成 closed-loop 验证；是否足以成为强通用 agent，仍必须靠跨卡组 BC、held-out deck 与 Arena 对战实证。

04 / BC objective

当前 BC 实际优化什么

label 是当前 simulator option list 中的 index set，而不是跨场景固定 action ID。单选、多选和空选共用同一合同。

单选：masked categorical CE只在合法候选 logits 内学习专家选择。
空选 / 多选：candidate BCE把每个合法候选当作独立 binary label。
数量：count CE学习 target count，并限制在 simulator 的 min/max 范围。
没有 reward / value lossterminal outcome 不进入总 loss，value head 当前没有可靠训练信号。
base = Norm(pool(Transformer(state_cards)) + MLP(state_64))
deck = pool(E_card + E_pos + MLP(deck_18))
entity = pool(E_card + E_pos + MLP(entity_28))
history = pool(E_card + E_pos + MLP(history_8))
expert = E_expert(expert_id)
h_state = Fusion([base; deck; entity; history; expert])

h_i = E_type + E_card + E_target + MLP(action_22_i)
logit_i = Policy([h_state; h_i])
count = CountHead(h_state)

L_policy = CE(logits, target) if |target| = 1
= BCE(logits, target_mask) otherwise
L_total = L_policy + CE(count_logits, target_count)

# terminal_outcome does not enter L_total
# value_head is not reliable yet

Rollout 未实现

用 BC policy 在 simulator 中采样完整对局，并保存 state、mask、action、old log-prob、reward 与 next state。

  • 必须沿用当前 candidate contract
  • 需要处理多选动作的联合概率

Reward / value 未实现

根据终局胜负和经过验证的 shaping 计算 return/GAE，同时真正训练并校准 value head。

  • terminal reward 可以很稀疏
  • 需要固定 perspective 与 reward profile

PPO update 未实现

冻结 old policy，在同一合法 mask 内计算 ratio 与 clipped objective，再回到固定评测护栏。

  • 不能把独立 BCE 直接当联合 action log-prob
  • 更新前后必须保持 schema/checkpoint 对齐

你的理解：核心方向正确

BC checkpoint 可以直接成为 RL policy 的初始化，并在真实 simulator 中推理和产生对战数据。随后用这些 transition 与终局结果定义 reward，再以 PPO 一类算法优化 policy/value，是合理的路线。

“无缝”的准确边界

无缝的是模型输入、候选动作和 checkpoint 初始化接口；不无缝的是训练数据合同。PPO 还需要 old log-prob、联合动作概率、reward/return/GAE、可靠 value 与 on-policy rollout，这些当前都不存在。

当前验证实验0003 · yushin_ito_exact_bc_v2

V1_card_token_regression 因卡牌 token 退化在 epoch 12 停止；V2_card_token_fix 达到 validation 80.52% / test 78.37%，并在 180 局官方引擎评测中取得 75.56% 胜率、0 errors。候选、dist 与 Kaggle ref 54912599 已归档，两个训练版本仍独立保留。

06 / What is still missing

距离强通用 agent 还缺什么

这里严格区分“张量已经存在”和“能力已经被验证”。新增输入只提供表达能力，不自动产生跨卡组泛化、隐藏信息推断或长程规划。

已实现

能进入当前模型、数据和 checkpoint 的合同。

  • 完整己方 deck conditioning
  • 双方场上实体与公开资源
  • 短期 action/effect history
  • expert source embedding
  • 结构化 card metadata
  • simulator legal action mask

只有部分表达 / 数据准备

有摘要或 source staging，但仍未形成被验证的能力。

  • Energy/Tool 只有数量，没有附着卡身份
  • 进化链只有深度，没有 stack IDs
  • 弃牌与手牌固定槽位可能截断
  • 卡牌效果只有结构代理，没有规则语义
  • 32 步压缩历史不是完整事件流
  • known Prize 与 Stadium 身份未显式编码
  • Top 20 已采样，完整 corpus / 20 个 checkpoint / Arena 对战尚未执行

尚未实现

不能把这些能力写成当前模型已经具备。

  • opponent deck / hidden-hand belief
  • determinization 或搜索
  • 多选动作的可靠联合 log-prob
  • 训练过并校准的 value function
  • RL rollout / reward / GAE / PPO
  • 多 expert 映射、跨卡组 BC 与 held-out deck 测试
下一步判断标准

0003 已经通过单专家 BC promotion gate：新表达提升了 validation/test exact 指标，test legal action 为 100%，标准 package 验证通过，并在官方引擎闭环对战中取得 136/180、0 errors。这个结果只覆盖 Yushin Ito 牌组。Top 20 已完成来源冻结和一局样本审计；后续每个替身仍要分别通过 source audit、held-out imitation、标准 package validate 和固定 evaluation，才可进入 Arena。
