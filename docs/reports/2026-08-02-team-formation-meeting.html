Attention 做关系，FFN 做逐 token 变换，Residual 保留旧信息。多层叠加后，模型把卡牌、区域、时机、资源和合法动作组织成可用于决策的表示。

Attention让每个 token 按当前问题，从其他 token 读取相关证据。

03.2 · QKV

Q、K、V：一个问题，一组索引，一组真正读取的内容

Q

Query · 我在找什么？

Attack option 的 Query 会问：能量够吗？伤害够吗？这次攻击会不会过早结束回合？

K

Key · 我是什么证据？

Active、手牌、Prize、对手 HP 等 token 产生 Key，让 Query 判断“这条证据与我有多相关”。

V

Value · 相关后读什么？

真正聚合的内容，例如手牌数量、攻击成本、进化时钟与对手目标价值。

Attention(Q,K,V) = softmax(QKᵀ / √d) · V
强调 Key 和 Value 不是缓存的同义词。推理里说 KV cache，是因为历史 token 的 K/V 可复用；Q 仍由当前 token 产生。

03.7 · BEYOND THE COMPETITION

如果这条路线继续做，价值在哪里

01

可迁移的表示

卡牌、区域、资源、合法动作和回合时机在不同 deck 之间有共性；共享 Encoder 可以减少每套 deck 从零开始的成本。

02

专项适配

把大部分参数冻结，只训练 deck-local decoder / value 或 adapter；算力增加后，能并行探索更多构筑。

03

可审计的实验

固定对手快照、版本目录、指标口径和提交 hash，让“有提升”能被别人复核，而不是停留在故事里。

写方案时只承诺这一点：这是一条有真实结果支撑、可以继续加数据、加 deck、加 GPU 和加工程投入的路线；不是全局最优的证明。

Team merge deadline、UTC 时间、每日/团队提交限制、合并后计数规则。

2 · 候选冻结

5 · 再提交

红线：不在 deadline 当天第一次演练；不让多人同时操作；不因 pending/低分自动重试；不把“应该还有额度”当作证据。

05.1 · BEFORE THE MERGE

合队前的价值，不是堆更多实验，而是制造一个 game changer

1
冻结一个可信 benchmark固定 catalog、seed、先后手、局数和 metric profile，所有新 idea 过同一把尺。
2
选择一个高杠杆变量不是同时改 deck、数据、模型、对手池和评测；只改一个能解释的变量。
3
用环境分析找非对称机会寻找 Top 100 集中弱点、低覆盖 deck 或稳定克制路径，而不是只追整体平均。
4
准备 Solution 证据包架构图、失败史、RL 同合同增益、scale-up 曲线、算力/人力边际收益。
