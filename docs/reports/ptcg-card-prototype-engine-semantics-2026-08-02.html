原始字段语义类型进入 token 的方式为什么不会混淆

        
cardId / attackId / skillId离散身份各自独立 embedding table表和 node type 都不同，不与数值相加后再猜类型

        
EffectType / TargetType / EnergyType有限类别按 enum family 分表 embedding同一个整数编号在不同 enum 中不会共享含义

        
hp / damage / count / effectValue可算术数值归一化 scalar + numeric MLP；保留单位/字段角色30 damage 与 30 cards 有不同 role embedding

        
onceTurn / seeingDeckBoolean0/1 value + presence/statefalse 与“字段不存在”不同

        
serial局内实体引用指向当前 entity token不是跨局稳定 ID，不建立全局语义 embedding

      


      

        
PAD 不得成为 Key/Value在 softmax 前加 -∞，不能只期待模型自己学会忽略。

        
PAD 输出不得池化mean/max pooling 和 decoder memory 都必须继续使用同一 valid-token mask。

        
结构关系必须显式parent、attack slot、pre/post effect 和执行顺序需要独立编码，不能只做无序求和。

        
截断必须 fail closed先审计全卡池最大长度；没有覆盖证据前，不允许静默截掉卡文尾部。

      

    


    

      
Preserve + Enrich Contract
不是重做 observation，而是把动态状态、历史知识和静态语义正确连接

现有能力一项都不应该删。
Prototype 回答“这张卡与这个动作原则上是什么”；observation 回答“这个实例现在是什么状态”；causal ledger 回答“玩家根据此前所见现在知道什么”；dynamic evaluator 回答“这个候选在当前状态下会产生什么确定结果”。四者不是替代关系。

模型合同部分处理理想输入/输出理由

        
原 observation entity/global完整保留当前实例、位置、数值、附着物、状态和回合预算Prototype 没有局面实时值，无法替代

        
ledger / event / known hand完整保留并重组独立 causal memory，带 exact/bounded/unknown 状态和 age单帧 observation 无法恢复曾经看过的牌库与手牌信息

        
registered deck multiset完整保留每种卡的初始数量、当前可见与隐藏区间，并连接 Card Prototype构筑定义游戏计划与剩余资源边界

        
Card ID dense semantics升级而非删除 identity保留 raw cardId embedding，同时增加 typed prototype token graph共享规则语义促进泛化，raw ID 保留卡牌独特残差

        
Option encoder必须修改显式 attackId/skill binding、effect/selection role、entity refs、prototype 和动态 delta只丰富 state encoder 不能修复 action identity 丢失

        
Engine action output合同保持仍输出 ordered legal option indices + STOP；logit 内部对应 enriched option官方引擎 legal options 继续作为合法性边界

        
可选辅助输出仅训练/probe预测 cost gap、resolved damage、KO、zone delta，禁止直接替代 policy logit验证 encoder 是否真的读懂语义，不把手工价值写进策略

      


      
所以“我们现在能做到这样吗？”答案是：账本和 multiset 已经有，完整连接还没有。
0022 已经构建 entity/global/zone、causal ledger、event、known opponent hand 和 exact-deck resource tokens，也已经让 option cross-attend board state；但 Card 语义仍是 96 维聚合表，moves 被做成数量/最大伤害/效果类别集合，具体 attack/effect 关系被压平，而且 option codec 丢掉 attackId。当前模型不是从零开始，但不能称为理想合同已完成。


      
不丢旧能力的迁移方式

      

        
01 · Parallel path旧 entity/global/ledger/option 路径保持不动，新 prototype 与 option delta 作为并行支路。

        
02 · Zero-gated init新支路以 zero-gated residual 接入，初始化时严格复现旧 logits，避免先破坏已有能力。

        
03 · Contract audit逐 option 校验 attackId/skill/effect 绑定、字段 presence、mask 和 actor-visible 边界。

        
04 · Sensitivity probes只改变能量类型、手牌数、HP/Tool 或攻击 ID，要求对应 option representation 与预测发生正确方向变化。

        
05 · Official-engine gate先做旧数据 parity 和 BC ablation，再以固定真实对局验证；覆盖不足或 prototype 截断一律 fail closed。

真正的风险不是“字段太多”，而是无区分地扁平化。
把 245 种 effect 全做成 dense columns 会稀疏、难审计；把所有 moves 求和又会丢关系。可变长 typed records 同时避免这两个问题。

Implementation Roadmap
先忠实抽取，再决定需要多少模型容量
这是一条可验证的工程路径，不要求第一版就重写完整模型。

      

        
01 · EXTRACT
只读 prototype sidecar
外部工具初始化官方 tables，完整序列化 Card/Attack/Skill/Effect/Target/Condition，写入 schema 与 source hash。

        
02 · AUDIT
覆盖率与有限性统计
统计每卡 attacks/effects 最大值、enum 使用分布、无法序列化字段；任何 truncation 必须 fail closed。

        
03 · BIND
actor-visible option binding
把 legal option 的 attackId/cardId/skill context 绑定到 prototype，并结合 causal ledger 生成动态 delta。

        
04 · ABLATE
用错误案例验证
固定模型容量，比较当前输入、静态 prototype、动态 readiness 三组；先验证 Ogerpon、Alakazam 与 Froslass。

      

      
进入更大模型或 MoE 的门槛
只有在关键信息已进入、final encoding 可 probe、当前 decoder 仍无法选择正确路线时，才把剩余问题归因于容量。否则先扩大网络只是在扩大对缺失字段的猜测能力。
