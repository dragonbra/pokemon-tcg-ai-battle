二、目的与共同原则

  1. 各方希望在明确的信息边界内共同研发、评测和提交 Simulation 竞赛 Agent，并共同完成 Strategy 竞赛要求的数据分析、方案和 Solution Write-up。
  2. 保密的目的在于保护团队尚未公开的研究成果、避免成果被无授权复制，并降低因违反 Kaggle 队伍及资源共享规则而被举报、取消资格或影响其他队伍的风险。
  3. 各方承认：本协议不是为了预设成员之间的不信任；它是对共同项目严肃性、责任边界和比赛合规义务的书面确认。
  4. 各方应以诚实、最小必要知悉、可追溯协作和遵守 Kaggle 当前有效规则为基本原则。

三、定义

保密信息
指由任何一方以书面、电子、口头、屏幕共享、代码仓库或其他方式向另一方提供，或成员在本项目中接触到的、尚未合法公开且具有研究、工程、竞赛或商业价值的信息。
项目资料
包括但不限于源代码、模型权重、checkpoint、训练配置、dataset、replay、trace、deck list、特征 schema、reward/value/PPO 设计、实验结果、对手池、提交包、submission hash、失败分析、Solution Write-up 草稿、商业化想法和路线图。
队外人员
未作为本次 Kaggle 队伍成员正式加入、未获得全体成员书面授权的任何自然人、团队、公司、实验室、线上群组、论坛用户、其他 Kaggle 队伍或其代理人。
公开信息
在相关成员披露前已合法公开，或经有权提供该信息的主体书面确认可以公开，且公开方式不违反 Kaggle 竞赛条款、隐私义务或第三方许可的信息。
竞赛期间
从 2026-08-02 起，至两项关联竞赛官方规定的提交、合队、评审、write-up、结果确认或争议期全部结束之日；具体日期以官方页面和本协议附录核验记录为准。
既有资产
指成员在 2026-08-02 前已独立合法拥有、能够以版本记录或其他合理证据证明，且不是从本项目其他成员处取得的代码、模型、数据、文档、发明或其他成果。

四、保密与限定使用义务

  1. 成员仅得为本队参加上述两项关联竞赛、内部研发、官方允许的评测和 Strategy 竞赛材料准备之目的使用保密信息，不得用于个人独立参赛、第三方项目、求职展示、商业推介或其他未获全体成员书面批准的目的。
  2. 成员不得向任何队外人员披露、转发、展示、上传、出售、授权、借用或以其他方式提供保密信息。禁止的方式包括私聊、邮件、云盘链接、公开/私有代码仓库、Notebook、截图、录屏、会议旁听和口头复述。
  3. 成员不得将未公开的本队代码、数据、模型、策略、deck、实验结论或写作素材复制到个人仓库、公共 Notebook、其他队伍 workspace 或未受本协议约束的第三方系统。
  4. 成员不得利用在本队获得的保密信息帮助其他 Kaggle 队伍，也不得把其他队伍的未公开资源带入本队。公开网页、公开 Notebook 和公开竞赛资料只有在不受额外限制且符合 Kaggle 规则时，才可作为公开信息使用。
  5. 成员应遵循最小必要知悉原则。涉及提交凭据、私有数据、账号、token、未发布 checkpoint 或商业安排的资料，不得因为“方便”而扩大访问范围。
  6. 下列信息不属于保密信息：接收成员能证明在披露前已合法知悉的信息；非因违反本协议而公开的信息；从有权披露的第三方合法取得且无保密限制的信息；以及接收成员未使用保密信息而独立开发并有同期记录证明的信息。
  7. 本协议不限制成员继续使用其不包含、也不能据以重构保密信息的通用知识、技能和经验；不得仅因成员在项目中提升了通用能力，就主张其后续正常学习或工作构成违约。

五、Kaggle 竞赛专项合规

口径：以下条款是团队的内部合规底线。Kaggle 的官方 Rules、Team、Code of Conduct 和 Competition 页面优先于本协议；任何冲突应立即暂停相关操作并由 release owner 核验。
  1. 禁止跨队伍共享未公开资源。在队伍合并、提交和评审相关期间，成员不得从本队向其他队伍提供，也不得从其他队伍获取未公开代码、模型权重、训练数据、deck、私有 notebook、策略细节、实验结果或提交包。
  2. 禁止借队、代投和隐性协作。成员不得使用未加入本队人员的账号或 workspace 执行研发、评测、提交或结果操作；不得通过“顾问”“朋友”“临时帮忙”等称谓规避队伍规则。
  3. 提交操作单一责任人。正式合队、打包、上传、查询 submission 状态和任何额外提交由指定 release owner 执行或在其现场监督下执行。其他成员不得擅自重试、替换包或改变提交说明。
  4. Team Leader 的指定。各方一致同意，由签署页所列成员 A担任两项关联竞赛在 Kaggle 平台完成正式组队后的 Team Leader。成员 A 的姓名与 Kaggle ID 应在签署前填写完整；未填写或不能唯一识别时，本项指定暂不具备可执行条件，但不影响本协议其他条款的效力。
  5. 合队及权限转移配合义务。如任何其他成员在签署时已经是相关 Kaggle 队伍的 Team Leader，该成员应在 Kaggle 规则、截止时间及平台功能允许的范围内，及时发起、接受或确认合并邀请，并在成员 A 正式进入合并后队伍后尽快完成 Team Leader 权限转移。其他成员应提供完成该操作所必需的合理配合，不得无正当理由拒绝、拖延、撤回邀请或另行指定与本协议不一致的队长。
  6. 平台限制与替代处理。任何成员均不得共享账号、密码、验证码或冒用他人身份来实现队长变更。若 Kaggle 页面不提供转移功能、官方拒绝合并或因非成员可控制的技术原因无法完成，各方应立即保存页面截图和操作记录，由当前 Team Leader 联系 Kaggle Support；在相关成员已经及时履行合理操作和通知义务的情况下，单纯的平台限制不构成其违约。在官方处理完成前，成员 A 作为团队内部合队协调人，但不得据此冒用 Kaggle Team Leader 权限。
  7. 队长权限边界。Team Leader 身份仅用于 Kaggle 平台所需的队伍管理与合规协调，不使成员 A 单独取得共同成果、既有资产、账号、奖金、署名或商业化权益，也不授权其未经本协议要求的同意程序单方公开资料、变更奖金分配、转让知识产权、排除成员或作出平台外承诺。
  8. 规则变化优先。本协议不得解释为允许绕过 Kaggle 的队伍数量、提交次数、时间节点、资源使用、公开发布、反作弊或知识产权要求。官方规则未确认前，不执行高风险操作。
  9. 留存合规证据。团队应保存规则页面 URL、截图、核验时间、操作者、submission ref、包 hash、状态和必要的会议纪要，以便在出现争议时说明信息来源和操作链。

六、允许披露的例外

  1. 成员可以向已经签署本协议、且确有必要知悉的本队成员披露项目资料。
  2. 经全体成员书面同意，成员可以向律师、会计师、税务顾问或信息安全顾问披露必要范围的信息，但应要求其承担不低于本协议的保密义务。
  3. 法律、法院、监管机关或 Kaggle 官方要求披露时，成员应在法律允许的范围内提前通知相关披露成员，仅披露必要范围，并保留要求和披露记录。
  4. 成员不能仅凭“对方不会使用”“对方也是朋友”“对方已经知道一部分”主张例外。

七、信息安全与事件报告

  1. 成员应使用个人独立账号和强密码，启用可用的多因素认证，不得在聊天记录、公共 issue、截图或日志中暴露 token、密码、私有 URL 或凭据。
  2. 发现误发、错配权限、账号泄露、私有仓库公开、设备遗失、疑似跨队资源交换或任何可能导致保密信息外泄的情况，应立即采取合理止损措施，并在发现后最迟 24 小时内 报告相关披露成员和团队安全联系人。
  3. 报告应包含：发生时间、涉及资料、接收方、已采取的撤回/吊销/删除措施、是否已经触及 Kaggle 规则以及需要的后续行动。成员不得自行隐瞒、删除证据或继续重试相关操作。
  4. 各方应先控制影响，再共同判断是否需要通知 Kaggle 官方、受影响第三方或法律顾问；任何外部说明应由全体成员指定的联系人统一发送。

八、知识产权、发表与 Solution Write-up

  1. 除非另有书面约定，本协议不转让成员在加入本队前独立拥有的代码、模型、数据、发明、论文或其他知识产权。成员应在附录中列明希望排除在共同项目之外的既有资产。
  2. 成员在本项目中共同产生的代码、模型、数据派生物、图表、文字、实验记录和方案素材，其归属、许可、署名、奖金分配和赛后使用方式应在提交前通过书面补充协议确认；本协议本身不自动约定平均分配或单方所有。
  3. 任何公开发布、开源、论文、演讲、博客、社交媒体、采访或对外路演，须经全体成员书面确认，并同时满足两项 Kaggle 竞赛当前规则、第三方许可、个人隐私和商业保密要求。
  4. Solution Write-up 的事实、图表和代码示例应由对应 owner 提供来源和口径。不能把内部假设、作者推测、未完成实验或队外未公开资料写成已证实事实。

九、期限、退出与资料处理

  1. 各方一致同意本协议自 2026-08-02 起生效，并适用于各方自该日起已经为本项目披露、接收或共同形成的信息。各签署人仍应如实填写其实际签署日期，不得倒签。保密和限定使用义务持续至两项竞赛相关活动结束后 24 个月；依法构成商业秘密的信息，在其合法保持秘密期间继续受保护。
  2. 成员退出、未参加最终提交或队伍发生变化，不影响其对退出前获得的信息承担本协议义务，也不自动授权其继续复制、使用或保留项目资料。
  3. 在资料提供成员书面要求、全体成员书面决议、成员退出或竞赛活动结束后，成员应在 7 日 内返还或删除其无继续保留必要的项目资料及副本；但共同仓库中的可审计记录按团队共同决定保留。法律或备份系统确实无法立即删除时，应采取隔离措施，不得继续访问或使用。
  4. 成员可以保留一份依法必须留存的合规记录，但该记录仍受本协议约束，不得用于研发、发表或竞争。

十、违约与争议处理

  1. 疑似违约发生时，各方应先暂停相关传播、访问和提交操作，保存证据并进行内部事实核验；不得因争议未定而继续扩大传播。
  2. 对于故意或重大过失造成的泄露、跨队资源共享、违规提交或账号滥用，受影响成员可要求立即停止、返还或删除相关资料，并依法主张能够证明的直接实际损失及合理维权费用。本协议不设置固定违约金、惩罚性内部罚款或任何成员可单方决定的赔偿金额。
  3. 各方应先进行善意协商，自书面提出争议之日起 15 日内未解决的，适用中华人民共和国大陆地区法律，并由被告住所地有管辖权的人民法院处理。签署人不在中国大陆或该约定不适用时，各方应在签署前另行书面约定。
  4. 若本协议某一条款被认定无效，其余条款仍然有效；各方应以最接近共同原意且合法的条款替代。
  5. 本协议构成各方就保密和竞赛合规事项的完整约定。任何修改、豁免或例外均须全体成员以可保存的书面方式确认，任何成员均无权单方面修改。
  6. 各方同意通过可靠电子签名、签字扫描件或分别签署相同文本的方式远程签署；各份签署页共同构成同一协议。签署人应填写其实际签署日期，不得倒签。
