This is the single-system view of the released BC + PPO policy. The numbered experiment ledger is preserved at archive/final-competition-repo-2026-09-13.

Data flow

official observation + legal actions
  → semantic prototype/state/option encoders (width 320)
  → frozen Policy-0814 BC backbone
  → rank-16 attention/FFN LoRA + final Option LayerNorm
  ├→ Actor decoder + allocation head
  └→ training-only win/prize/meta Critic
Identity gate: focal and opponent are independently materialized complete policies. Critic outputs and hidden exact-deck identity never enter Actor logits.

Training and evaluation

ptcg-train creates U0 directly from committed Policy-0814 Actor and Value assets, then collects 512 official-engine CUDA games per PPO update. Every five updates it runs a fixed greedy Policy-0814 exact-deck CUDA-512 evaluation. Checkpoints are complete model-only deltas.

Deployment

Candidates use FP16 storage followed by strict FP32 runtime loading and deployment-effective hashing. The public router consumes only public, certain opponent Pokémon evidence. The retained selection-set CUDA-2048 report is 1,382–666–0 against complete Policy-0809; it is not an independent holdout or automatic promotion.
