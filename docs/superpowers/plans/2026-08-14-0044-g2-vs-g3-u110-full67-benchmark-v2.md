> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Evaluate Champion-G2 and V10/G3 U110 on every focal deck 001–067 under identical Benchmark V2 CUDA-2048 jobs, then publish a live per-deck, per-Meta, and per-opponent comparison report.

**Architecture:** Use V5 U0 as the audited zero-residual Champion-G2 deployment checkpoint and V10 U110 as the G3 candidate checkpoint. A restart-safe V11 controller runs two isolated subprocess arms per focal deck, prioritizes 007/003/002, randomizes the remaining deck order with a frozen seed, and atomically republishes the Combat HTML after every completed pair.

**Tech Stack:** Python 3, PyTorch, CUDA Engine 2.0, official engine runtime, Benchmark V2 common-random schedule, pytest, static HTML/JSON.

- Do not modify `engine/source/`.
- Each arm must strict-materialize under `kaggle_fp16_storage_fp32_runtime_v1` and record PASS candidate/opponent identity audits.
- Both arms use complete immutable Policy-0809 opponents and the same 2,048 engine/Search/policy/coin seeds.
- G2 source is exact V5 U0 SHA-256 `3ee103ed721a5f5771d0c07c13598bd19b1f4ead71765740442c85891600be06`.
- G3 source is exact V10 U110 SHA-256 `e1101f1712f2e4751aa56ba983b1a1165a9852b4cb1ab18913fbcd6108beac79`.
- Execution order begins `007, 003, 002`; remaining decks are a deterministic permutation recorded in state and manifest.
- A deck is complete only after both 2,048-game arms PASS; partial directories never count as evidence.
- Publish under `docs/evaluation/combat_mat/benchmark_v2/` and update after every complete deck pair.
