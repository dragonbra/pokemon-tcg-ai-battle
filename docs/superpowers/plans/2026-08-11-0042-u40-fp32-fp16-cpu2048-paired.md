# 0042 U40 FP32/FP16 CPU-2048 Paired Diagnostic Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure U40 raw-FP32 versus Kaggle FP16-storage/FP32-runtime outcome and greedy-action differences on the exact same Policy-0809 CPU-2048 schedule.

**Architecture:** Add a diagnostic-only runner that rebuilds the already-completed FP16 schedule from its recorded deployment identity, runs a raw-FP32 U40 focal model against the independently materialized full Policy-0809 opponent, and compares outcomes by immutable `game_id`. During every FP32 focal strategic request, a frozen FP16 shadow model receives the exact same collated observation and legal options; root compound actions and Phantom Dive allocation wires are compared before the FP32 action is sent to the official engine.

**Tech Stack:** Python 3.11, PyTorch FP32 inference, official CPU engine workers, CUDA batched neural inference, JSON diagnostic artifacts, pytest.

## Global Constraints

- This is raw-FP32 diagnostic evidence only; it is ineligible for Kaggle strength, Frozen Promote, or automatic promotion.
- Opponents must resolve independently to complete immutable `Policy-0809` with the existing effective-policy audit `PASS`.
- The game schedule must reconstruct the FP16 reference schedule SHA-256 exactly; do not derive seeds from the raw-FP32 identity.
- The primary FP32 and shadow FP16 models must be separate module instances with no shared parameter/storage.
- Official CPU engine semantics, 007 exact focal deck, 55-deck frequency unit, toss behavior, and per-lane exact-deck routing remain unchanged.
- The existing FP16 report remains immutable and is read-only input.
- Do not modify PPO, reward, GAE, optimizer, formal Frozen gates, or `engine/source/`.
