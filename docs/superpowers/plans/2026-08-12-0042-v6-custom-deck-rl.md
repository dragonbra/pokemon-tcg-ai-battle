# 0042 V6 Custom-Deck RL Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Start an unbounded formal `V6_dragapult_ex_0042_v6` PPO branch from V5 update 130 with the audited `dragapult_ex_0042_v6` exact 60-card focal deck.

**Architecture:** Make focal deck identity a per-run immutable `RunConfig` input rather than changing the project-wide Frozen 007 constants. Resolve the deck once before model/opponent materialization and pass the same tuple, ID, hash, display name, and source through rollout jobs, own-archetype initialization, checkpoint metadata, candidate FP16 materialization, and periodic Frozen CUDA-2048. Preserve all V5 optimizer/PPO and full Policy-0809 opponent semantics.

**Tech Stack:** Python 3, PyTorch PPO, resident official CUDA engine, W&B, unittest.

## Global Constraints

- Version is `V6_dragapult_ex_0042_v6`; deck ID is `dragapult_ex_0042_v6`.
- Branch source is V5 `update-000130.pt`; optimizer is fresh and checkpoint update restarts at 0.
- Rollout is 256 games/update with exact 55-deck Policy-0809 frequency unit and 256 CUDA lanes.
- PPO Protocol V2 stays at minibatch 2048, max 3 epochs, actor decoder/allocation LR `2e-5`, policy adapter LR `4e-5`, value LR `1e-4`, clip `0.10`, entropy `0.003`, reference KL `0.02`, Meta anchor `0.10`.
- Periodic Frozen evaluation runs every 10 updates under FP16 storage → strict FP32 runtime against independent full Policy-0809.
- Training is unbounded and stops only at an update boundary through `artifact/STOP_REQUESTED`.
- Official `engine/source/` remains read-only.
