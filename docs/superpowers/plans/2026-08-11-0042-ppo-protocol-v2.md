# 0042 PPO Protocol V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace 0042's fixed optimizer budget with complete, auditable PPO data epochs, then validate it with a 256-game preflight, a 16-update smoke, and a gated 128-update formal baseline.

**Architecture:** Each rollout is prepared once and retains immutable behavior log probabilities, old values, advantages, and returns. PPO shuffles all valid decisions without replacement for up to three complete epochs; an end-of-epoch full-buffer behavior-KL probe controls further reuse. Optimizer telemetry separately counts examined and actually optimized samples.

**Tech Stack:** Python 3.11, PyTorch, CUDA official-engine rollout infrastructure, pytest, JSONL/TensorBoard/W&B logging.

## Global Constraints

- Use exactly 256 games per update and preserve one complete 256-game frequency unit.
- Use minibatches of 2,048 decisions, `drop_last=false`, and at most three complete data epochs.
- Keep rollout-frozen old log probability, old value, normalized advantage, and return targets across all epochs.
- Use AdamW FP32 with actor LR `5e-6`, value-exclusive LR `1e-4`, no scheduler, zero weight decay, and max grad norm `0.5`.
- Use target behavior KL `0.015` and hard behavior KL guard `0.025`, evaluated over the full buffer after complete epochs.
- Keep gamma `1.0`, GAE lambda `0.95`, same-turn lambda `1.0`, terminal bootstrap zero, reference KL `0.02`, and Meta anchor `0.10`.
- Do not modify `engine/source/`, promote a champion, or alter the official Frozen policy registries.
- Retain model-only checkpoints for every update; formally evaluate the requested U0/U32/U64/U96/U128 milestones.
