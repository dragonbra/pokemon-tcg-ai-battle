# 0042 V11–V16 Deck Curriculum Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop V11 after its U50 Frozen evaluation, then run V12–V16 serially for focal decks 003, 006, 009, 010, and 011, with every version inheriting the previous version's U50 model-only checkpoint and stopping after its own U50 Frozen evaluation.

**Architecture:** A project-local fail-closed curriculum controller waits for the current segment, verifies its U50 checkpoint, sidecar, Frozen-0809 CUDA-2048 result, and identity audits, then launches exactly one next formal version. Future segments use finite `--updates 50`, which makes the trainer complete only after U50 evaluation and persistence; each segment starts a fresh optimizer/RNG/on-policy stream and derives own-archetype conditioning from its exact 60-card focal deck.

**Tech Stack:** Python 3, PyTorch PPO Protocol V2, resident official CUDA engine, systemd user service, W&B online, unittest.

## Global Constraints

- Sequence: V11/001 → V12/003 → V13/006 → V14/009 → V15/010 → V16/011.
- V11 stops only after U50 checkpoint exists and U50 Frozen evaluation finishes.
- V12–V16 each use exactly 50 updates and inherit only the preceding version's `update-000050.pt` model weights; optimizer, RNG, rollout, and replay state are fresh.
- Every transition requires complete Frozen-0809 CUDA-2048 evidence: 2,048 unique terminal games, zero error/unfinished/semantic fallback, candidate deployment PASS, and opponent Policy-0809 PASS.
- All V11 training parameters remain unchanged except focal exact deck, derived own-archetype class, finite 50-update duration, version, and source checkpoint.
- Candidate evaluation remains FP16 storage → strict FP32 runtime; PPO remains FP32; all checkpoints are retained.
- The controller must fail closed and must never skip, resume, overwrite, or concurrently run two curriculum versions.
- Official `engine/source/` remains read-only; promotion remains human-only.
