# Limitless TEF-POR 环境对比分析设计

## 目标

以 Limitless TCG 的 `time=all&type=all&format=TEF-POR&region=all&division=all`
筛选结果为历史线下赛环境边界，全量分析该格式下 8 场大型赛事，并与仓库
`docs/environment-daily_kaggle_top100/daily/2026-07-30.html` 的 Kaggle Top 100
冻结快照进行对比。最终交付一个可离线查看、证据可追溯、交互完整的
`docs/environment/limitless.html`，重点回答环境形成原因、牌型克制关系、公开对局胜率、
构筑变种、代表选手与后续训练启示。

## 证据边界

- Limitless 环境边界固定为用户提供 URL 中的五个筛选参数，不用当前默认格式替代。
- 采集到的赛事列表必须恰好与筛选页一致。初始核查为 8 场、10,923 名参赛者；正式生成时
  重新核对赛事 ID、日期、名称、地区和人数，不能把初始观察直接写成未验证事实。
- Limitless 的 `Share` 是站点按赛事成绩积分计算的环境份额，不等同于参赛套数占比；页面同时
  展示原始 Points、Share 和可重建的构筑/选手计数，禁止混用。
- Kaggle 对照固定为 2026-07-30 Top 100 的榜单席位、exact deck 和官方 Episode Meta。
  Kaggle 席位占比不是线下赛选择率，官方 Episode 胜率也不是线下 BO3 胜率。
- 对局统计仅使用公开且能绑定双方身份、牌型和结果的 pairings。缺失赛事或缺失轮次不填零，
  必须列出赛事级覆盖率与缺失原因。
- 线下赛事公开信息存在选手能力、地区、赛事阶段、ID/tie 和构筑公开范围偏差。报告可以识别
  统计关联和稳定优势信号，但不得把观察性数据单独宣称为严格因果意义上的“天然克制”。

## 数据采集与审计

### 筛选合同

正式采集首先解析目标 decks 和 tournaments 页面，并保存以下审计字段：最终 URL、抓取时间、
活动筛选标签、赛事 ID 列表、赛事人数总和、未拆分牌型 Points/Share、拆分 variant 后的
Points/Share。必须验证：

1. 活动筛选标签为且仅为 `format: tef-por`；`time/type/region/division=all` 不得意外收窄。
2. 赛事列表为 8 场且人数合计 10,923；若站点数据发生变化，以实时结果为准，但必须在报告中
   标注与设计时初始核查的差异并重新审查边界。
3. 未拆分与拆分后的 Points 总量一致，允许显示百分比四舍五入误差。
4. 每场赛事详情声明的 format 与 TEF-POR 时间范围一致；异常赛事 fail closed。
5. 多龙一级总量与其二级 variant 之和可解释；站点的未标注 Dragapult 作为独立子型保留。

### 本地资产

- 采集与分析实现放在 `data/processed/environment_limitless/`，不向 `scripts/` 增加入口。
- 网络响应缓存放在 Git ignore 的 `.tmp/environment_limitless/`，便于复核且不提交第三方整页副本。
- 提交级事实数据使用紧凑的聚合 JSON，记录来源 URL、时间、分类版本、赛事覆盖、牌型分布、
  matchup 单元格、代表构筑和代表选手；完整网页和无关广告内容不进入仓库。
- HTML 使用冻结后的聚合数据生成。统计复算与页面渲染分离，避免从展示文本反向解析事实。

### 牌型分类

采用两级牌型合同：

- 一级为 Limitless 主 archetype，例如 Dragapult、Raging Bolt、Alakazam、Festival Lead。
- 二级优先采用 Limitless variant ID，并用实际 60 卡列表验证关键进化线或引擎组件。
- 多龙至少区分：未标注基础型、Dusknoir、Dudunsparce、Blaziken，以及 TEF-POR 数据中实际出现
  且样本非零的其他官方 variant。混合变种按站点 variant 归类，同时在构筑审计中列出关键卡。
- 若站点标签与实际卡表冲突，保留原标签、记录冲突，并建立 `unresolved` 审计项；不得静默改名。
- 其他一级牌型在样本量足以影响矩阵时同样拆分。热力图保留主要细分类，低样本长尾聚合为
  `Other`，但详情表仍保留原始类别与统计。

## 统计方法

### 环境分布

同时报告 Points Share、可见构筑数、赛事覆盖数、Top Cut/最高名次和代表选手。Kaggle 对比使用
席位差、排名差、Top-2/Top-5 集中度、HHI 和 Jensen-Shannon divergence；只在映射明确的同类牌型
间计算对应差值，无法映射的牌型单列。

### Matchup

每个有向 matchup 单元格保存 `wins/losses/draws/n`，并展示：

- 原始胜率：`wins / n`；
- 有效胜率：`(wins + 0.5 * draws) / n`；
- 95% Wilson 区间，基于有效胜场口径计算；
- 赛事数、独立选手数和数据覆盖说明。

证据等级固定为：

- `n >= 30` 且 95% 区间完全高于或低于 50%：较可信优势或劣势；
- `15 <= n < 30`，或区间跨过 50%：方向性信号；
- `n < 15`：样本不足，只展示原始记录，不推断克制。

镜像单元格必须满足 W/L 对称、draw 相等、样本量相等。自对局只用于评估同型内部波动，不进入
“克制”排序。若公开来源只给瑞士轮 match score、不提供逐 game 结果，报告明确以 BO3 match 为单位。

### 代表选手与构筑

代表性评分综合 TEF-POR 最佳名次、跨赛事稳定性、历史 Limitless 成绩和构筑代表性，不以单场冠军
自动替代长期实力。每个主要牌型展示至少一名代表选手；多龙主要子型分别展示代表玩家和真实
60 卡构筑。构筑分析区分核心卡、常见投入、可变槽位和个人特例，并链接原始赛事、选手和卡表。

## 结论框架

报告按三层解释环境差异：

1. 规则和卡池相同部分：卡牌文本、攻击节奏、Prize trade、spread damage、资源循环等机制。
2. 竞赛制度差异：线下 BO3/瑞士轮/平局与 Kaggle 自动高频 BO1、确定性策略、榜分和样本规模。
3. 策略生态差异：人类构筑成熟度、技术上限、对手分布、agent 实现难度、合法动作与规划能力。

多龙专题必须把“线下份额高”拆解为实际子型贡献、对局覆盖、构筑工具箱和玩家表现；Kaggle 中缺席
不能直接解释为卡组弱，而要检验是否更可能源于策略实现、训练覆盖和当前 agent opponent 生态。
训练建议必须区分“应加入 opponent curriculum 的牌型”“应单独训练的 deck-specific policy”和
“数据不足，暂不调整”的项目，遵守仓库 BC + RL 与候选 package 准入约定。

## HTML 信息架构

页面继承 2026-07-26 日报的紧凑、可审计视觉语言，但不复制日报数值。采用以下完整导航：

1. 结论摘要与证据护栏；
2. Filter 与 8 场赛事审计；
3. Limitless 环境分布和集中度；
4. Kaggle 0730 并列对比与差异量化；
5. 多龙环境核心专题；
6. 一级与二级构筑变种分析；
7. 代表选手、历史成绩与 exact deck；
8. 全牌型 matchup 热力图；
9. 多龙细分 matchup 放大热力图；
10. 优势、劣势与证据等级表；
11. 环境成因、克制解释和训练建议；
12. 数据覆盖、方法、来源链接与局限。

页面自包含 CSS/JavaScript，支持牌型筛选、热力图单元格 tooltip、表格排序、卡图大图预览、移动端
横向滚动和打印。不得用卡片层层嵌套；长表以固定表头和清晰密度为主。颜色不单靠红绿区分，所有
色块同时显示数值、样本量和证据标记。

## 错误处理

- 网络失败使用有上限的读取重试，但不能对提交、登录或其他写操作重试；本任务只有公开只读采集。
- 页面结构变化、筛选未生效、赛事数量/人数异常、variant 总量不守恒或 matchup 镜像不一致时，
  生成器返回非零，不覆盖已有权威 HTML。
- 部分 pairings 不可访问时允许生成，但必须降低 matchup 覆盖并在页面显著标注；如果没有任何可审计
  pairings，则不生成伪热力图，改为“当前公开数据不可重建”。
- 第三方卡图失败时显示文字 fallback，不影响统计内容。

## 验收与复核

数据验收包括筛选参数、8 场赛事、10,923 人、Points/Share 守恒、60 卡构筑、variant 关键卡验证、
matchup 镜像、总样本数、百分比和置信区间复算。结论复核逐条反查支持数据，检查是否把相关性写成
因果、是否忽略小样本、是否误用 Kaggle 与线下赛口径。

HTML 验收包括核心 section ID、表格行数、热力图维度、所有外链、卡图组件、移动端和桌面端截图、
控制台错误、文字溢出与交互状态。最终必须运行相关单元测试、完整仓库测试或与改动风险相称的测试、
HTML 结构检查，并在交付时给出可点击文件路径和实测数据覆盖摘要。
