# Limitless 环境报告卡图 UI 优化设计

日期：2026-07-30

## 目标

在不削弱环境统计可读性的前提下，让 `docs/environment/limitless.html` 中每个被讨论的具体卡牌都能被立即识别。整体体验对齐 `docs/environment-daily_kaggle_top100/daily/2026-07-30.html`：正文以文字为主，用小卡图作为识别锚点；悬浮或点击时显示完整大图；完整构筑直接展示 Pokémon、Trainer、Energy 的全量卡图。

## 信息层级

### 正文与关键结论

- 具体卡牌名称使用紧凑的内联卡牌引用：小卡图、卡名和必要时的系列编号。
- 鼠标悬浮显示不遮挡当前段落的高清预览；键盘聚焦提供相同信息。
- 点击打开可持久查看的高清弹窗，移动端以点击交互为主。
- 牌型简称不是具体卡牌时，附 1–3 张最能区分该牌型或副轴的代表宝可梦卡图。
- 卡图是文字的辅助证据，不用图片替代胜率、样本数、Wilson 区间或证据等级。

### 表格与热力图

- 环境分布、变种、代表选手、克制关系和训练建议中的牌型名称附紧凑代表卡图。
- 热力图行列标题使用稳定尺寸的代表卡图组和短名称，正文格尺寸不因图片加载而变化。
- 宽表继续在局部容器横向滚动，不产生页面级横向溢出。
- 同型内战、无样本和低样本证据语义保持不变；卡图优化不得改变统计数据。

### 完整构筑

- 19 份代表构筑继续保持 exact 60-card 审计边界。
- Pokémon、Trainer、Energy 三组全部使用环境日报式卡图网格展示。
- 每张卡展示投入数量、卡名、系列和编号；点击进入同一高清预览组件。
- 桌面端使用自适应多列，移动端至少两列；卡图容器使用固定宽高比，加载状态不得造成布局跳动。
- 同一张卡的不同印刷版本按构筑记录中的系列和编号显示，不以同名卡随意替换。

## 数据与解析

- 在生成阶段建立统一卡牌注册表，键为规范化的 `set + number`；卡名只用于展示和辅助匹配。
- 19 份 exact decklist 是构筑区卡牌身份的权威来源。
- 正文、结论和牌型代表图优先引用已冻结代表构筑中的卡牌身份；缺失时从 `data/official/` 的当前官方卡牌数据解析。
- 每个正文卡牌引用和每个牌型代表图都必须在生成时解析成功；无法唯一解析时 fail closed，不生成错误卡图。
- 图片 URL 使用 Limitless 当前卡图 CDN 的小图与中图规格，并在 HTML 中保留卡名、系列、编号和来源信息。

## 交互组件

- 小图悬浮预览使用单例浮层，自动避开视口边缘和当前文字。
- 高清弹窗沿用现有 `dialog`，增加系列编号、前后浏览、关闭按钮、Escape 和焦点恢复。
- 内联卡牌引用和卡图按钮均可键盘聚焦，并提供完整 `aria-label`。
- 图片加载失败时显示固定尺寸占位及卡名，不隐藏引用或破坏文本行高。
- 尊重 `prefers-reduced-motion`，预览只使用轻量淡入，不加入持续动画。

## 视觉约束

- 保持当前报告克制、审计型的视觉语言，并吸收日报的卡图网格与预览体验。
- 正文小图不超过约一行半文字高度；表头代表图使用固定小尺寸；完整构筑才使用可阅读卡面的较大图片。
- 不使用嵌套卡片堆叠，不把每句结论包成独立大卡片，不用卡图挤占胜率与样本信息。
- 桌面和移动端均保证文字、按钮、卡图、热力格不重叠。

## 验收合同

- 所有页面中被标记为具体卡牌的引用都能解析到唯一的系列和编号，并存在小图与大图 URL。
- 所有牌型表、细分多龙表、热力图标题和关键结论都包含代表卡图。
- 19 份代表构筑仍全部精确为 60 张，且 Pokémon、Trainer、Energy 每一项都有卡图入口。
- 悬浮、点击、Escape、关闭、键盘聚焦和移动端点击行为通过浏览器测试。
- 390px 移动端无页面级横向溢出；热力图和宽表只在自身容器滚动。
- 原有 18 项数据与统计测试继续通过，并新增卡牌注册表、引用完整性和渲染合同测试。
- 最终使用桌面、移动端、正文卡图悬浮、热力图和展开构筑截图进行视觉复核。

## 非目标

- 不重新抓取或改写 Tournament、pairing、胜率和环境分布数据。
- 不改变 Labs 牌型标签、Kaggle 名称映射或 matchup 证据分级。
- 不把所有普通名词误识别为卡牌，也不根据相似名称猜测不唯一的印刷版本。
