设计结论

0010 已经让合法 option 作为 Query cross-attend 到 state Key/Value。下一步不应建立“本局候选下标 → Action ID”的记忆表，而应消除候选顺序捷径、补齐稳定的结构化动作语义，并让 action representation 接受可观测状态变化的辅助监督。

先修捷径

移除 option_position 依赖，通过候选随机置换训练和一致性测试，确认模型选择动作语义而非 simulator 排序。

再修语义

分离 source 与 target，显式编码 attack/effect/context，避免共享 embedding 相加造成方向信息减弱。

最后补预测

从相邻 observation 构造所选动作的 observable delta；它能改善表示，但仍不是未选择动作的反事实 Q 值。

冻结的共同实验合同

所有实验只改变声明的 feature 或 architecture。数据身份、切分、训练预算和评测池保持一致，避免把新数据、训练时长或随机波动误认为结构收益。

当前 0010 的结构性缺口

Action 已是 Query，但仍有 shortcut

option token 包含候选列表位置；source/target area、card、slot、entity gather 使用共享表后相加，可能利用排序并弱化 source → target 方向。

动作 primitive 不完整

固定卡组使 card ID 有效，但同一实体的不同 attack、ability、effect/context 仍缺少完整、稳定的组合 identity。

State 主要是当前截面

有公开实体与 turn flags，但缺少显式动作历史、关键卡资源账本、跨决策时间和稳定的 attachment relation。

Loss 只问专家选了什么

token CE 不要求模型解释 zone、damage、hand/deck、KO 或 turn-end 变化，动作后果只能间接涌现。

九个实验方向：按重要性排序

编号是研究优先级，不表示九项全部串行累加。排序综合当前缺陷确定性、单变量可归因性、BC 收益、实现风险和未来复用价值。

逐项实验设计

1

E1 · Candidate permutation invariance

最高优先级Feature + transform低成本

假设

option_position 让模型记忆 simulator 候选排序。删除它并随机置换候选、同步重映射标签，应提高置换鲁棒性。

变量

  • 移除 position embedding。
  • 每次取样置换 candidates。
  • 用 inverse permutation 重映射每个 target index。

通过条件

  • 原始 validation exact 非劣界 −0.2 pp。
  • 置换前后 semantic action 一致率 ≥99.5%。
  • permutation KL 显著下降。
注意：置换的是候选列表，不是专家多选动作的选择顺序；STOP、selected order、min/max count 均不变。
2

E2 · Role-separated structured action

Architecture方向语义

假设

共享表相加会产生角色混叠；角色专用投影更能区分“用 A 作用于 B”和反方向。

变量

首版使用独立 W_source/W_target 处理 owner、zone、slot、card、entity；E2b 再试 [CLS, VERB, SOURCE, TARGET, PAYLOAD, CONTEXT] 小 Transformer。

通过条件

  • source/target slice exact 上升。
  • 同 card、多 target 决策改善。
  • 交换角色的反例表示不再近似相同。
3

E3 · Action primitive and context completion

Feature低参数增量

假设

card ID + option type 无法稳定区分同一实体的不同 attack、ability 或 effect step。

新增字段

  • attackId、effect ID、context-card ID；
  • selection type/context、effect step；
  • decision phase、min/max count、pointer step。

通过条件

  • attack/effect/context macro 指标上升。
  • rare context 不被总体常见动作掩盖。
  • 非零率、基数、OOV audit 通过。
4

E4 · Chosen-action observable transition auxiliary

Auxiliary objective高信息价值高成本

假设

预测下一可观测变化，会迫使 action-conditioned representation 编码动作效果，而非只拟合选择相关性。

目标

  • hand/deck/discard/prize delta；
  • zone move、switch、damage；
  • energy/tool/evolution delta；
  • draw/search/attach/retreat/attack/KO/turn-end。

通过条件

  • 只从冻结 replay identity 派生。
  • 报告 target coverage/accuracy。
  • BC exact/NLL 也改善；只降辅助 loss 不通过。
边界：不得给未选择候选伪造 transition。跨多个 effect step 的动作必须先定义 prediction horizon、终止条件和 mask。
5

E5 · Turn history and temporal state

假设

相同场面因本回合已执行动作、实体进场时间或 effect chain 不同而需要不同选择。

变量

最近 N 个 typed action、actor/source/target/effect serial、relative distance、same-turn flag、entered/evolved turn。

通过条件

按 turn/depth/effect-chain slice 改善；新对局 history reset 测试通过；无未来 action/result 泄漏。

6

E6 · Fixed-deck resource ledger tokens

假设

搜索、过牌、回收和进化需要知道关键资源在各 zone 的分布，而不是只看 deckCount。

变量

每个 card ID/family 的 initial、hand、field、discard、known prize、unknown、remaining bounds 和 known mask。

通过条件

与固定 60 卡 audit 一致；search/recovery/evolution slice 改善；不泄漏对手隐藏牌。

7

E7 · Relation-aware entity encoder

假设

Energy、Tool、preEvolution 与宿主是图关系；绝对 parent index 依赖遍历顺序。

变量

relation bias/edge tokens：attached-energy、tool-on、evolves-from、same-owner、same-zone；加入实体置换测试。

通过条件

entity permutation consistency；attach/evolve/retreat/attack slice 改善；capacity control 有效。

8

E8 · Legal-option set encoder

假设

让 options 先互相注意，可能更好表达多个 target 或资源用途的相对机会成本。

变量

action-to-state cross-attention 后增加 1–2 层无绝对位置的 set Transformer，再进入 GRU pointer。

通过条件

大候选集、同 type 多 target、多选 slice 改善；保持置换等变；报告 latency 随 M 的变化。

9

E9 · Hybrid card identity and semantics

假设

固定卡组中 ID 很强，但 category、Stage、HP、type、retreat、attack cost/effect primitive 可提供组合归纳偏置。

变量

card_repr = ID embedding + typed metadata encoder；state、action、ledger 共享 encoder；首轮不引入自由文本模型。

通过条件

同参数预算下 BC 改善并提供 metadata 分组消融；若固定卡组无收益，不强行进入组合版本。

统一指标与验收合同

同时测“模仿更准”“没有错误捷径”“官方 engine 无退化”。单看 validation exact 或单看 230 局胜率都不充分。

层级必须报告用途
BC 主指标token NLL/accuracy、semantic exact、free-greedy exact同时看概率质量与完整自由解码。
结构 slicesingle/multi、option-count、type/context、turn、source/target、attack/effect防止简单常见决策掩盖复杂失败。
鲁棒性candidate/entity permutation consistency、KL、字段 coverage/OOV检查 simulator/遍历顺序 shortcut。
统计按 episode/player group cluster bootstrap 的 Δexact/ΔNLL 95% CI避免把同一 episode 内 decision 当独立样本。
工程params、MiB、samples/s、peak memory、inference speed、NaN/illegal/error控制 capacity 与部署成本。
官方评测W-L-D、error/unfinished、先后手、逐对手、回合数、固定 profile唯一策略强度证据。

进入组合候选

合法 100%；鲁棒性通过；主指标有 cluster 证据，或严格非劣下修复明确 shortcut；官方评测无可归因退化。

保留为中性基础

BC 非劣，显著改善 permutation/coverage/可解释性，并为 E4 或未来 value head 提供必要输入。

停止累加

存在未来泄漏、重映射错误、复杂 slice 退化、capacity control 无收益或新增 runtime error。

建议执行顺序

  1. Phase 0 · Audit：建立 semantic action canonicalizer、candidate permutation remap test、字段 coverage audit；同预算重跑 0010 control。
  2. Phase 1 · 最小高价值：分别运行 E1、E2、E3；全部随机初始化，不继承其他实验 checkpoint。
  3. Phase 2 · 表示学习：在 Phase 1 选出的共同 action foundation 上运行 E4；E5/E6 仍作为独立 feature ablation。
  4. Phase 3 · 结构扩展：E7–E9 只在前面证据表明仍受 state/option 表示限制时执行，并提供 capacity control。
  5. Phase 4 · Champion stack：只组合有独立证据且语义互补的模块；组合版本也必须新训练，不覆盖失败 run。

需要 Review 确认的决策

  1. 是否接受 E1–E3 作为首批实现，E4 先做标签可行性 audit。
  2. 是否固定 0010 optimizer/training budget，首轮不同时搜索 LR、depth、width。
  3. 是否采用 semantic exact + permutation robustness 作为新增主要离线合同，并保留原始 token loss/exact。
  4. E2 首版采用轻量 role-specific projection；六个 action sub-token Transformer 留作 E2b。
  5. 正式 experiment ID、版本 tag、随机种子数量和完整官方评测批次，在实现前单独冻结。
